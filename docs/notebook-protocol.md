# Jupyter Notebook 编写协议

## 适用范围与规则归属

本协议适用于现有和后续课程的全部教学 Notebook，包括本地草稿。编写、修改或验收前，读取[项目协作协议](../AGENTS.md)、本文件及拟归属课程的 `AGENTS.md`；运行环境见课程 README，知识范围见课程 plan。

本文件只维护 Notebook 的组织、格式、资源标注与执行方法。全局教学、最简代码、来源、依赖及检查范围由根协议维护；课程补充协议只说明技术差异，不另立相反的通用规则。

## 课程编写的七条原则

七条原则完整维护在[根协议](../AGENTS.md#课程编写的七条原则)。本节保留原有入口供旧链接定位，不再复制规则正文。

## 节点与教学组织

每章以一份 Notebook 为唯一教学正文。一个知识点优先采用一个 Markdown 单元介绍、一个 Code 单元演示；简短操作、参数与结果说明优先放在相邻代码注释中。定义、必要推导、概念关系和需要展开的结果分析使用相邻 Markdown；预期输出仍在相邻代码注释中给出。以下只细化展示方式，不改变全局的最简代码、预期输出与真实性要求。

| 内容或执行方式 | 单元组织 |
| --- | --- |
| 内核直接执行的示例 | Markdown 介绍紧接 Code 单元，保存实际执行输出 |
| 纯理论、公式与必要推导 | 使用 Markdown 数学排版，不强制配代码，不塞进代码注释 |
| 原生脚本、编译或浏览器代码 | 在 Markdown 中用对应语言代码块展示，紧邻知识点；实际运行必要配套文件，不增加 Python 包装或生成文件魔法命令 |
| 逐类绘图 | 仅在课程协议明确采用时，将简短的适用场景、数据、参数与观察点写成一个 Code 单元内的注释；复杂机制、推导和需要展开的读图分析使用相邻 Markdown |
| 开篇、导航、小结、练习、引用 | 按各自职责组织，不机械套用两个单元 |

复杂知识点可以分步，每一步保持说明与示例相邻；高度相关的观察可放在同一单元。不要为满足单元数量删去必要上下文或将长流程硬塞进一个单元。

Python 内核的文本与数值观察用 print()，不依赖单元末尾表达式自动显示，不用分号抑制输出；自行输出并返回 None 的查看方法可直接调用。图形使用工具要求的显式展示接口，其他语言使用控制台、页面或相应工具输出。具体工具选用由课程协议细化。

## 每篇 Notebook 的结构

| 位置 | 编写要求 |
| --- | --- |
| 开篇 | 第一个 Markdown 单元含唯一一级标题，依次列“学习目标：”“前置知识：”；环境、工作目录与资源入口按下文列出 |
| 主知识点 | 连续编号的二级标题，如“## 1 数值类型”；使用具体主题名 |
| 必要子知识点 | “### 1.1 整数”等三级标题；通常不再增加 1.1.1 层级 |
| 组织性标题 | 只作共同入口时给必要导语，不强加代码，不保留空标题 |
| 示例 | 按执行方式组织，预期及简短操作解释写在相邻代码注释中；需要展开的分析可用相邻 Markdown，不重复转述输出 |
| 本章小结 | 使用“## 本章小结”，归纳关键要点与理解自查 |
| 练习 | 使用“## 练习”，题目、提示、解析分开；完成任务所需输入就地提供 |
| 参考与引用来源 | 使用“## 参考与引用来源”，固定为最后一个 Markdown 单元，其后不追加单元 |

小结、练习和来源不参与知识点编号。正文不增加“验证记录”“核对内核”，不添加专门打印解释器路径或环境信息的代码单元；检查结果的保存位置按根协议处理。

### 开篇写法

- “学习目标：”一句话概括本章实际收获，不复制目录或列入未编写内容；“前置知识：”只列概念或操作，没有专门要求时写“无需编程基础”等明确说明。
- 有版本或运行方式条件时单列“运行环境：”；“环境准备：”链接所属课程 README；有执行内容时单列“工作目录：”。内核章节说明从该目录启动、重启内核后顺序运行；纯浏览器或编译章节说明其实际方式，不要求不存在的内核。
- 章节保留必要输入、命令、浏览器入口和关闭方式，不复制整套环境安装。一个服务的启动与关闭在开篇说明一次，各节只补充自己的入口。运行步骤按根协议使用 Step 写法。
- 有必需配套源码、页面、样式或配置时列“配套脚本：”，用简短列表提供相对于 Notebook 的文件链接与用途；独立数据另列“数据：”。没有相应文件就省略该项。
- 文件名、源码与资源目录按根协议组织。链接使用正斜杠，实际路径不得夹带 Markdown 转义；移动后同步更新头部、正文、命令和代码中的路径。

### 阅读与排版

- 同一知识点的短段落放在同一个 Markdown 单元中，用空行分开含义，不逐句拆单元。并列规则可以用编号或无序列表，同组格式一致。
- 总览表逐项保留原文名称及“中文名称／含义”，必要时增加用途、可变性或作用对象；多个需要分别理解的名称不挤在一行。HTML 标签、CSS 属性等具体总览范围按课程协议限定，章末来源表不属于知识点总览表。
- 使用标准 Markdown 与数学排版，不依赖自定义字体或 CSS。Notebook 正文术语、名称与短代码不用反引号行内高亮；此项不限制独立 Markdown 工程规范。特殊字符按需转义，代码块使用正确语言标记。
- 去掉单元首尾空白行，不追加空单元。代码能清楚写在一行时不人为拆行，语法需要或续行教学除外。
- 不把来源核查、编写过程与验收流程写进教学导语，不重复堆叠“问题、依据、成功标准”等标签。摘录或节译明确标识，普通解释不使用伪引用块。

## 配套脚本文件头

读者阅读或运行的每个源码文件独立标注四项信息：所属章节、演示知识点、运行命令、期望结果，每项一行。仅被导入的支撑模块也标注，运行命令写实际章节入口；共享模块的所属章节写首次讲解章，可补充复用主题。数据、图片、JSON 配置、锁文件和构建产物不加代码文件头。

| 文件类型 | 位置与语法 |
| --- | --- |
| Python | 文件首的模块 docstring |
| JavaScript、TypeScript | 文件首的 // 注释块 |
| HTML | 紧随 doctype 的 HTML 注释块 |
| CSS | 文件首的 CSS 块注释 |

所属章节与 Notebook 名称一致；知识点只写本文件实际演示内容；命令与正文逐字一致并注明工作目录；期望结果写一句要点，预期失败写明错误和非零退出。文件头不替代相邻代码注释，命令与行为变化时同步维护。

## 图示的制作与整合

- 本节适用于所有现有及后续课程。辅助解释原理、关系、结构、算法或流程的示意图统一放在所属课程的 image/illustration/，包括自行绘制和按许可引用的示意图；按用途分类，不按 SVG、PNG 等格式分类。教学代码生成的结果图、绘图教学示例和真实操作截图等仍放 image/，不迁入 illustration/；Notebook 内保存的图形输出不要求另存。
- **先选图源，再选画法。** 先查找官方文档、正式标准、原始论文或作者／维护者发布资料中的权威原图；有适合本节且可用的原图时优先采用，没有可用原图时再依据已核查的权威资料自行绘制。逐图核对具体内容、版本、模型变体、假设和适用条件是否支持当前讲解，同时确认出处可追溯、授权允许所需使用方式、实际显示清晰；只有相关文字或相近主题，不代表已有可直接替换的官方图。
- 原图为英文、配色不同或变量名不同，本身不构成改用自绘的理由，可用中文图注、术语对照及正文衔接帮助理解。若原图与学习目标不符、无法清晰展示或无法确认使用条件，不直接收录；自绘仍须核查知识依据，不能用描摹未获许可原图规避使用条件。原图保留原有风格，不为统一配色强行改绘；其实际格式为 PNG 等位图时可以原格式采用，不要求转成 SVG。
- 图注区分“引用原图”“依据原图改绘”和“依据原理自行绘制”，写明必要的来源名称、署名及简化条件。裁剪、翻译或改绘须符合原图许可并明确标识；具体来源链接、图号／小节／页码、版本及必要许可信息按网站汇总到章末“参考与引用来源”，保留原图要求的署名或声明。不另建通用图片来源档案，不能用图的引用代替正文知识点核查。
- 示意图文件采用“章节-序号-名字.扩展名”：章节为所属 Notebook 的二位章节号，序号为该章示意图的二位编号，从 01 开始，名字使用简短的英文小写 kebab-case。例如 image/illustration/03-01-gradient-descent.svg 或 image/illustration/03-02-update-step.png。初次整理按图在正文中的出现顺序编号，后续新增图使用该章下一个可用编号，已有编号保持稳定；同一图跨章复用时引用原文件，不重复复制或改号。
- 扩展名与实际文件格式一致，SVG 保留 .svg，不为命名示例转换为 PNG。仅在有实际图片时创建目录；移动或改名后同步更新正文、文档及必要代码中的引用，并核对文件存在与实际渲染。
- 确需自绘时，含文字、公式、维度或精确连线的结构图、流程图和算法示意图采用直接编写的 SVG，或用 Python 绘图库绘制；非必要不使用图像生成模型直接生成图片，避免文字模糊、乱码和关系失真。数值图表由实际数据与绘图代码生成，截图来自实际操作，不用引用图或人工示意替代真实实验输出。
- 自绘图的视觉参考为阿里云 AI Agent Handbook 的[浅色分组流程图](https://github.com/aliyun/ai-agent-handbook/blob/d2cd22d27e2c1053923439a86008ccf56545f54c/assets/imgs/chapter-09/image-003.svg)与[曲线示意图](https://github.com/aliyun/ai-agent-handbook/blob/d2cd22d27e2c1053923439a86008ccf56545f54c/assets/imgs/chapter-17/image-007.svg)。这里只参考配色、线条、留白和文字层次，不复制图中内容，也不将其作为其他技术知识的依据。采用白色或浅灰背景、深色文字、少量蓝／绿／紫语义分组、浅色填充、细边框和清楚箭头；参考色为背景 #F8FAFC、文字 #192D43、蓝 #245B93、绿 #166D69、紫 #68518B、边框 #CBD5E1，可按对比度与图意调整。
- 布局服从知识关系：树、矩阵、几何关系、算法迭代和流程各用适合的形式，不机械套用架构框图或固定长宽比。箭头方向、实虚线及颜色的含义保持一致，必要时给图例；不能仅靠颜色区分关键关系。减少交叉连线、过密文字与装饰，让符号、维度和步骤对应正文及代码。
- 仅供作者制作或验收插图的临时 Python 脚本放在 drafts/，不作为课程配套交付；需要读者学习、运行或复用的绘图代码按正文及配套脚本规则组织。图文件按上述用途归类，正文通过相对路径引用。
- SVG 保留清晰可缩放的文字，设置支持中文的常见字体及回退；Python 绘图选择当前环境实际可用的中文字体，检查数学符号、负号和特殊字符。位图按实际展示尺寸导出足够分辨率，不能通过放大低清图片冒充清晰版本。
- 图前交代要理解的关系，图注说明箭头、符号及简化条件，图后连接公式、代码或观察任务；同步改写重复或不再准确的相邻讲解，不能只插入一张图。已有图表或交互示例足以表达时不重复配图。
- 在 Notebook 的实际阅读宽度检查文字、公式、连线、图例与缩放效果，修正重叠、裁切和乱码；文件可解析不等于可读。发现图示不清晰或关系表达不准确时，先评估可用权威原图，再决定替换或重绘，不用模糊图片承载关键知识。现有图片分别评估图源适合性与绘制质量；不能仅因不是自绘、不是 SVG 或配色不同判定不合格，符合要求的图保留。

## 练习与预期异常

- 可运行练习逐题用“题目 Markdown → Code”组织，提供输入、待预测语句或注释占位；不使用未定义变量、无条件报错占位。纯理论或浏览器操作题按实际任务提供可验证要求，不为形式增加空 Code 单元。
- 重点题提示与解析放在题目之后并清楚分隔，可采用分层提示；不得在待预测语句旁提前透露答案。练习内容与反馈尺度按根协议及必要课程要求执行。
- 条件变化在题干明确，输入或代码就地提供；解析保留题干约定，说明各变体的结果和原因。重要变体按真实执行方式核对，不以原始例子通过代替变体检查。
- 普通 API 错误需要作为反例展示时，用独立 Code 单元直接产生原始异常，注释说明原因与异常类名；正常操作和错误例子分开，不加入“捕获后打印再断言”包装。是否使用异常捕获由根协议第六条决定。
- 预期异常单元的 metadata.tags 加入 raises-exception，metadata.expected_exception 写预期异常类名。后者是本项目的验收约定，不代表执行工具自动完成类型匹配。
- 验收默认不全局允许错误；只对明确标记的反例允许继续。检查该单元确实产生异常，实际类型与声明一致，并确认后续正常单元完成。“未报错但应报错”“类型不符”“未标记单元报错”均为失败。
- 使用 NBClient 等工具时，执行后由作者或验收逻辑完成上述逐单元核对；仅设置 raises-exception、允许某类错误或执行到结尾，均不能单独证明反例通过。预期错误脚本与编译用例按课程协议核对原始诊断和退出状态。

## 环境与执行

检查范围与重跑触发条件以[根协议](../AGENTS.md#协作与验收)为准，本节规定实际执行方式。

- 含 Code 单元的章节按课程 README 准备所需内核；解释器归属在作者检查时核对，不写成教学单元。执行从空内核开始，自上而下运行，保存真实输出与计数。
- 不依赖其他 Notebook 运行产物。交互输入预先说明并用实际输入检查；服务、外部资源、下载或付费操作按已明确条件执行，不偷偷替换为模拟结果。
- 纯 Markdown 的原生脚本、编译或浏览器章节不要求内核计数；实际运行对应文件。混合章节分别检查内核输出、编译诊断和浏览器交互，不用其中一种检查代替另外一种。
- 仅改文字或注释时，核对语义和旧输出仍一致；源码展示、回溯、行号或生成内容受影响时，重新运行相应示例，不手工修补输出。不确定是否改变行为时按代码变更检查。
- 选学只有入口说明时，不冒充已执行；提供了可执行示例时，报告实际覆盖与未执行条件，不以选学名义把未运行代码计入“全部通过”。
- 检查完成后关闭实际创建的服务与资源，清理临时产物。必要清理采用最小可理解写法，不添加吞错或成功假象。

## 参考与引用来源规则

知识依据、逐点核查和授权要求以根协议为准。Notebook 只在最后一个 Markdown 单元维护来源，使用“网站／本章参考内容与定位”两列表格。

同一实际站点一行，合并支持的知识点与页面，保留每个直接链接、小节、版本、论文页码或源码位置；不只给站点首页。独立文档站点分别列出，同一托管平台的不同项目或论文合并时保留各自名称、用途与定位；多个版本说明对应关系。

只列实际核查并用于本章的资料；推荐图库或学习入口在确实用于本章且注明用途时可列出，不能作为未核查知识的依据。插图的来源、图号和必要许可信息合并到该表，保留原图要求的署名。

## 章节验收

按根协议确定本次检查范围，再核对以下项目：

- 章节主题、标题、开篇字段、小结、练习和篇末来源完整；教学单元组织符合根协议和适用展示特例。
- 按根协议的理解标准逐节核对用途、规则、条件和结果解释；必要推导和复杂类型关系不能只留结论。检查练习是否直接回答题干，图表分析是否支持本章要求的方法判断。
- 示例、注释、预期、配套源码、输入路径和文件头一致；没有用于防备假设中非法输入的多余分支与异常包装。
- 知识、公式和图片的来源定位真实存在并直接支持当前内容及适用条件，跨库比较核对各端来源；图中文字、公式、连线与实际阅读宽度下的显示清楚。
- 应运行的代码、编译项目与浏览器交互已按各自方式检查；预期异常得到逐单元核对，失败范围如实说明。
- 仅改说明时核对保留输出的适用性，不宣称重跑；不保留空单元、验证记录段落和临时作者产物。

预期错误执行的工具边界参照 [NBClient force_raise_errors](https://nbclient.readthedocs.io/en/latest/reference/nbclient.html#nbclient.client.NotebookClient.force_raise_errors) 与[官方实现](https://github.com/jupyter/nbclient/blob/main/nbclient/client.py)中的 _check_raise_for_error；异常类名和“必须报错”的逐单元比较属于本项目检查约定。
