# Jupyter Notebook 编写协议

## 适用范围与规则归属

本协议适用于现有和后续新增课程的所有教学 Notebook，包括本地草稿；编写、修改或验收前必须读取并遵守。以下七条原则同时约束正文代码块和随章示例；从课程规划与样章开始应用，后续章节和修订保持一致。

本文件保存通用的 Notebook 写作与验收要求。[AGENTS.md](../AGENTS.md)规定项目范围、知识来源和依赖管理原则；代码写法按实际语言读取[对应编程规范](../AGENTS.md#编程规范)，包括随章辅助代码。环境配置见所属技术目录的 README.md；技术专属的展示、排版与检查要求见该目录 AGENTS.md。编写前一并读取，专属要求在其范围内适用，用户最新明确要求优先。

## 课程编写的七条原则

1. **教学单元简洁成组。** 每个知识点优先采用“一个 Markdown 介绍 + 一个代码示例”的组合；代码操作步骤和结果解释写在相邻注释中。复杂内容按学习步骤拆分，不强行合成长代码，也不限制整章只有两个单元。理论推导、浏览器或编译型语言、图表绘制的展示方式按下文及技术目录协议细化，其余原则照常适用。

2. **注释帮助理解代码。** 长代码必须用简洁中文解释关键步骤，复杂短代码也须补充必要说明。重点解释用途、参数含义、数据形状、单位、状态变化和处理原因，避免逐行复述语法；多步骤主流程可用编号注释，多行数据或参数按语义分组。修改代码时同步更新相关注释与 docstring。

3. **输出旁明确预期。** 每处供读者观察的输出，都在相邻注释中说明预期，包括 print、console、表格、图形和页面交互。固定结果写具体值、类型或顺序；表格写关键行列、形状和缺失特征；图形和页面写应看到的内容及操作后的变化。连续输出可合用注释，但须逐项对应；不只写“输出结果”或解释调用动作，也不复制整张表。

4. **区分固定结果与运行差异。** 随机样本、耗时、临时路径、进程号与请求标识说明稳定特征、合理范围或字段关系；引用实测值时注明“本次”，不承诺每次相同。浮点误差重点说明数量级和必要容差，不要求复现细小尾数；样本值与理论值分开说明，精确值直接写明。

5. **命名简短且清楚。** 函数名和变量名优先简短、明确，避免冗长名称和重复前后缀，也不为缩短而使用难懂缩写。保留必要单位和对照关系；公式惯用的短名称就地解释含义，不机械缩写公开 API、协议方法或测试名称。

6. **只保留必要分支和异常处理。** 教学输入条件明确时，直接完成当前操作，删除多余的类型、范围、环境检查、兜底和 try 包装，让普通异常直接暴露；不用三元表达式或布尔短路变相隐藏多余防御。算法、业务规则、交互、接口契约、资源清理以及条件判断或异常处理教学所必需的 if、try 保留。校验或正确性核对本身属于学习目标时，保留必要检查。

7. **保持教学目的与结果真实。** 保留已有清楚的注释；预测练习先让读者预测，注释只写运行后的核对维度，不提前给答案。错误示例注明原因和预期异常，注释须与代码及真实结果一致；仅补注释时保持原有逻辑、输出行为与练习要求。正文片段和配套文件同步维护，交付时区分静态检查、已有输出核对和实际重跑。

## 节点与教学组织

- 一份 .ipynb 围绕一个明确的章节主题，可以包含服务于同一主要学习目标的多个相关知识点。按学习关系划分章节，不固定文件数量，也不把每个术语或例子机械拆成一篇。
- 从具体用途和小例子引入，先讲基本用法，再说明必要机制与边界；多个独立学习目标或过长的前置知识链需要拆章。基础章不强制加入底层原理、手算、图表或性能实验。
- 两单元组合适用于一个知识点的介绍与示例，不强加于开篇、小结、练习和引用。公式与必要推导保留 Markdown 数学排版，不塞进代码注释；独立理论说明可不配代码。使用原生脚本或浏览器的课程，可在 Markdown 中紧邻说明展示带语言标记的代码块，并实际运行配套文件；逐类绘图按课程协议将说明与代码合入一个 Code 单元。
- Notebook 是该章唯一的教学正文，目录 README.md 只提供范围说明或运行入口。按[项目协议](../AGENTS.md#jupyter-notebook-内容规范)先写正文与最小示例，再按讲解需要添加配套文件；多文件包、命令行、服务等主题可配套必要源码，完整项目归 projects/。
- 必需的章节专用脚本及其资源默认放在 Notebook 所属技术目录的 scripts/章节/ 下，章节目录使用二位序号与英文小写 kebab-case，例如 scripts/08-modules-and-packages/。技术目录补充协议可将落盘教学数据集中到 data/，将已讲解的跨章模块放在 scripts/ 下可直接导入的位置；可导入模块和包使用 snake_case，不以含连字符的章节目录作为包名。公共流程首次在正文展开，再按需抽取；不得隐藏当前教学重点或依赖其他 Notebook 的运行状态。仅在实际需要时创建，不建立空目录或占位脚本；检查结束后及时清理临时脚本和运行产物。
- 文件名采用“二位章节序号-规划表中的章节名称.ipynb”，例如 01-基础语法.ipynb；一级标题为“基础语法”。按章节编写时直接放在技术目录，不为单章增加重复分类层级；可导入的 Python 模块和包仍使用 snake_case。
- 先在本地草稿中确认基础样板，再逐篇展开；通过来源核查与实际验证后，按任务要求整理到正式目录。

## 配套脚本文件头

- 读者按 Notebook 指引打开或运行的代码文件，在文件头用固定标签标注四项信息：所属章节、演示知识点、运行命令、期望结果，各占一行；写法与位置见下表。JSON 配置、数据与图片资源、生成的构建产物不写此文件头。
- “所属章节”写二位序号与章节名称，与 Notebook 文件名一致；“演示知识点”只写本文件实际演示的内容，不罗列全章；“运行命令”与正文命令逐字一致并注明工作目录；“期望结果”写一句话要点，预期失败的示例写明预期错误和非零退出。
- 多文件章节中，被读者直接阅读或运行的每个代码文件独立标注；仅被导入的支撑模块同样标注，运行命令写章节入口命令。文件头只做定位与运行入口，与行内注释、文末检查说明不重复复述；命令或预期变化时同步更新。具体语法和技术特例见对应技术目录 AGENTS.md。

| 文件类型 | 文件头写法与位置 |
| --- | --- |
| Python | 模块 docstring，位于文件首 |
| JavaScript、TypeScript | `//` 注释块，位于文件首 |
| HTML | `<!-- -->` 注释块，紧随 `<!doctype html>` 之后 |
| CSS | `/* */` 注释块，位于文件首 |

## 每篇 Notebook 的结构

| 位置 | 编写要求 |
| --- | --- |
| 开篇 | 第一个 Markdown 单元使用唯一的一级标题，依次单列“学习目标：”和“前置知识：”，再简述适用版本和必要运行条件；“环境准备：”链接到本技术目录 README.md；有配套文件时补充“配套脚本：”及用途清单 |
| 主知识点 | 使用连续编号的二级标题，如“## 1 数值类型”；标题写具体内容，不用“知识点”代替名称 |
| 必要的子知识点 | 使用“### 1.1 整数”等三级标题，仅在有独立讲解与观察目标时拆分；通常不继续增加 1.1.1 等层级 |
| 讲解与代码 | 按七条原则组织简短 Markdown 介绍与一个代码示例；由内核运行的示例使用 Code 单元，其他展示方式见“节点与教学组织”及技术目录协议 |
| 组织性标题 | 二级标题若只是多个子知识点的共同入口，可只写必要导语，不强加代码；避免只有层级作用的空标题 |
| 结果说明 | 预期结果、检查方法和结果解释写在对应代码注释中，实际输出由执行生成；代码后不另加结果说明单元 |
| 本章小结 | 使用“## 本章小结”，归纳关键要点与理解自查，不重复全文 |
| 练习 | 使用“## 练习”，写明任务、可验证标准及必要提示；答案或提示与题目分开 |
| 参考与引用来源 | 使用“## 参考与引用来源”，作为最后一个单元，按网站汇总实际核查的来源 |

本章小结、练习和参考与引用来源不参与知识点编号。Notebook 不编写“验证记录”和“核对内核”部分，不添加专门打印解释器路径或环境信息的代码单元；实际检查结果只在当次交付说明中报告。

### 开篇写法

- “学习目标：”用一句话概括学完本章能理解什么、完成什么操作，与实际正文对应，不重复罗列章节目录，也不把尚未编写的内容列为已覆盖目标。
- “前置知识：”遵循[项目协议](../AGENTS.md)的独立文档原则，只简列所需概念或操作，例如“变量赋值、容器操作、解包”。没有专门要求时直接写明，例如“无需编程基础”。
- 环境准备只链接到所属技术目录 README.md；安装工具、创建环境和安装整套课程依赖的步骤集中维护。章节保留实际版本条件、工作目录、输入、运行命令及关闭方法，不重复完整准备流程。
- 配置与运行按“Step 1：一句话说明 → 一个命令块”列出，一步只做一件事；界面操作写一句具体操作。条件紧邻对应步骤，不把多个命令、分支和长段解释挤在同一步。首次准备和日常运行按需分开。
- 环境管理、编译、打包等本身属于章节学习目标时，保留对应教学讲解和示例；不因安装步骤集中到 README.md 而删除知识点。
- 有必需的配套文件时，在头部写“配套脚本：”及相对于 Notebook 的实际位置；默认是 scripts/章节/，跨章模块按课程协议列出实际模块路径。随后用简短编号列表说明用途并提供相对链接；单独管理的数据以“数据：”列出路径和说明入口。没有配套文件时省略相应项；文件移动或改名后同步更新头部、正文链接、代码路径和命令示例，并重新检查受影响的代码或浏览器操作。
- 头部、正文和命令中的项目内路径写成完整的相对路径。代码中的固定路径也放在一个字符串内；有变量时只连接完整固定后缀，不逐级拆分目录名称。课程路径写法和起点说明见对应技术目录 AGENTS.md；Markdown 链接使用正斜杠，路径中的下划线转义不得带入实际文件名。

### 讲解与措辞

- 用熟悉、具体的词说明用途和行为，再引入必要术语。避免一段集中引入多个未解释的概念；必须提前使用本篇后文的工具时，先简述当前用途，必要时指向本篇相应小节。
- 采用通行专业译法，对照官方或第一方原文确认含义，不自创术语或逐词硬译，也不把某一份官方中文译文视为唯一正确译法。易歧义、译名不统一或不直观的术语首次附英文原名，同一概念前后保持一致。
- 库名、API 和工具名称保留原文，必要时附简短中文含义或用途，不强行另造中文名称。
- 同一对象属于不同分类，或同一概念在不同章节出现时，如容易混淆，用一句话说明分类关系或本章侧重点，例如“list 既是 Python 内置类型，也属于容器”；不重复展开已有讲解。
- 写法或公式中的 x、y、n 等占位符首次出现时就地说明所指对象；必要时写明类型、取值范围、单位或维度。说明紧邻公式或表格，不让读者从后文代码猜测。
- 保留有助于区分语法的操作数。例如 +x、-x 中，x 代表参与运算的数值；应解释 x 的含义，并用具体数值示例说明写法，不直接删去 x。表中只列运算符时，也应另给完整写法或示例。
- 删除重复导语、写作流程、无关抽象概念，以及对代码和注释的重复复述；保留必要条件、易错边界和相似概念之间的区别。

### 阅读与排版

- 一个自然段围绕一个意思，用空行区分用途、基本规则和易错边界，不堆成长段，也不逐句硬换行。同一知识点的分段留在同一个 Markdown 单元内。
- 多个并列规则可列项，默认用中文括号编号“（1）”“（2）”，也可用“①”“②”；同组格式一致，每项单独成段，不为一两个短句机械列项。
- 类型、术语或 API 总览表保留原文名称，并增加“中文名称／含义”列；每个独立项目一行、一一对应，例如 set 对应“集合”，frozenset 对应“不可变集合”。用途、可变性、示例等列按当前主题选择，不将多个需要分别解释的名称合并在一格。
- 去掉单元首尾空白行，篇末不追加空单元。代码能清楚写在一行时不人为拆行，语法要求或演示续行除外。
- 使用标准 Markdown 与代码单元，不依赖自定义字体或 CSS。正文中的术语、名称与短代码使用普通文字，不用反引号生成行内高亮；Markdown 特殊字符按需转义，确保符号和表格正确显示。
- 按[项目协议](../AGENTS.md#jupyter-notebook-内容规范)按需加入截图或示例图，以相对路径引用并提供说明与替代文本。辅助讲解的示意图放在课程 image/illustration/，教学代码生成的图、实际截图等正文图片仍放 image/；命名与归类见下文。代码生成的图形优先在对应单元直接展示并保存真实输出，不要求逐张导出再读回；需要正文引用、复用或导出时再保存图片文件。训练用图像等数据集按课程数据目录约定存放，网页运行所需资源按配套文件规则组织。
- 减少重复的“问题、官方说明、依据、成功标准”等标签。来源核查、单元编排和验收过程不写进教学导语；必要的节译说明可在开篇统一标明，引用块只用于明确标识的摘录或节译。

### 图示的制作与整合

- 本节适用于所有现有及后续课程。辅助解释原理、关系、结构、算法或流程的示意图统一放在所属课程的 image/illustration/，包括自行绘制和按许可引用的示意图；按用途分类，不按 SVG、PNG 等格式分类。教学代码生成的结果图、绘图教学示例和真实操作截图等仍放 image/，不迁入 illustration/；Notebook 内保存的图形输出不要求另存。
- **先选图源，再选画法。** 先查找官方文档、正式标准、原始论文或作者／维护者发布资料中的权威原图；有适合本节且可用的原图时优先采用，没有可用原图时再依据已核查的权威资料自行绘制。逐图核对具体内容、版本、模型变体、假设和适用条件是否支持当前讲解，同时确认出处可追溯、授权允许所需使用方式、实际显示清晰；只有相关文字或相近主题，不代表已有可直接替换的官方图。
- 原图为英文、配色不同或变量名不同，本身不构成改用自绘的理由，可用中文图注、术语对照及正文衔接帮助理解。若原图与学习目标不符、无法清晰展示或无法确认使用条件，不直接收录；自绘仍须核查知识依据，不能用描摹未获许可原图规避使用条件。原图保留原有风格，不为统一配色强行改绘；其实际格式为 PNG 等位图时可以原格式采用，不要求转成 SVG。
- 图注区分“引用原图”“依据原图改绘”和“依据原理自行绘制”，写明必要的来源名称、署名及简化条件。裁剪、翻译或改绘须符合原图许可并明确标识；具体来源链接、图号／小节／页码、版本及必要许可信息按网站汇总到章末“参考与引用来源”，保留原图要求的署名或声明。不另建通用图片来源档案，不能用图的引用代替正文知识点核查。
- 示意图文件采用“章节-序号-名字.扩展名”：章节为所属 Notebook 的二位章节号，序号为该章示意图的二位编号，从 01 开始，名字使用简短的英文小写 kebab-case。例如 image/illustration/03-01-gradient-descent.svg 或 image/illustration/03-02-update-step.png。初次整理按图在正文中的出现顺序编号，后续新增图使用该章下一个可用编号，已有编号保持稳定；同一图跨章复用时引用原文件，不重复复制或改号。
- 扩展名与实际文件格式一致，SVG 保留 .svg，不为命名示例转换为 PNG。仅在有实际图片时创建目录；移动或改名后同步更新正文、文档及必要代码中的引用，并核对文件存在与实际渲染。
- 确需自绘时，含文字、公式、维度或精确连线的结构图、流程图和算法示意图采用直接编写的 SVG，或用 Python 绘图库绘制；非必要不使用图像生成模型直接生成图片，避免文字模糊、乱码和关系失真。数值图表由实际数据与绘图代码生成，截图来自实际操作，不用引用图或人工示意替代真实实验输出。
- 自绘图的视觉参考为阿里云 AI Agent Handbook 的[浅色分组流程图](https://github.com/aliyun/ai-agent-handbook/blob/d2cd22d27e2c1053923439a86008ccf56545f54c/assets/imgs/chapter-09/image-003.svg)与[曲线示意图](https://github.com/aliyun/ai-agent-handbook/blob/d2cd22d27e2c1053923439a86008ccf56545f54c/assets/imgs/chapter-17/image-007.svg)。这里只参考配色、线条、留白和文字层次，不复制图中内容，也不将其作为其他技术知识的依据。采用白色或浅灰背景、深色文字、少量蓝／绿／紫语义分组、浅色填充、细边框和清楚箭头；参考色为背景 #F8FAFC、文字 #192D43、蓝 #245B93、绿 #166D69、紫 #68518B、边框 #CBD5E1，可按对比度与图意调整。
- 布局服从知识关系：树、矩阵、几何关系、算法迭代和流程各用适合的形式，不机械套用架构框图或固定长宽比。箭头方向、实虚线及颜色的含义保持一致，必要时给图例；不能仅靠颜色区分关键关系。减少交叉连线、过密文字与装饰，让符号、维度和步骤对应正文及代码。
- 仅供作者制作或验收插图的临时 Python 脚本放在 drafts/，不作为课程配套交付；需要读者学习、运行或复用的绘图代码按正文及配套脚本规则组织。图文件按上述用途归类，正文通过相对路径引用。
- SVG 保留清晰可缩放的文字，设置支持中文的常见字体及回退；Python 绘图选择当前环境实际可用的中文字体，检查数学符号、负号和特殊字符。位图按实际展示尺寸导出足够分辨率，不能通过放大低清图片冒充清晰版本。
- 图前交代要理解的关系，图注说明箭头、符号及简化条件，图后连接公式、代码或观察任务；同步改写重复或不再准确的相邻讲解，不能只插入一张图。已有图表或交互示例足以表达时不重复配图。
- 在 Notebook 的实际阅读宽度检查文字、公式、连线、图例与缩放效果，修正重叠、裁切和乱码；文件可解析不等于可读。发现图示不清晰或关系表达不准确时，先评估可用权威原图，再决定替换或重绘，不用模糊图片承载关键知识。现有图片分别评估图源适合性与绘制质量；不能仅因不是自绘、不是 SVG 或配色不同判定不合格，符合要求的图保留。

## 最小代码与注释

代码可读性、命名、输出预期和分支取舍统一按上述七条原则执行；本节补充展示方式、反例与练习的具体要求。

- 每个代码单元承担一个清楚的观察目的，高度相关的现象可合并观察。使用小型输入和直接写法，不为格式添加无关类、配置层、包装函数或未介绍的高阶语法。
- 教学单元可直接写表达式和语句，不机械套用 main() 入口；配套脚本仍遵守脚本规范。Python 内核中的文本和数值观察用 print() 显示，不依赖单元末尾表达式的自动显示，也不用分号抑制输出；自行打印、返回 None 的查看方法可直接调用，图形使用工具要求的显式展示接口。其他语言使用相应的控制台、页面或工具输出方式。需要由内核运行的教学代码放在 Code 单元执行，不能只贴在 Markdown 代码块中。
- 输入尽量就地给出；依赖前文导入或定义时明确说明，不能依赖其他 Notebook 或历史执行遗留的隐藏状态。
- 反例只在有助于理解重要边界、常见误解或实际风险时保留。普通语法错误可简述，不为证明简单错误提前引入测试框架、动态执行等高阶机制。
- 可执行反例须明确说明预期异常或错误结果。普通 API 报错可用独立 Code 单元直接展示原始异常，不添加“捕获后打印再断言”的包装；单元注释写清原因和异常类型，metadata.tags 使用 raises-exception，metadata.expected_exception 记录预期异常类名。正常示例与预期报错单元分开，交互运行遇到该例报错后继续下一单元。只有讲解异常处理本身或需要实际恢复、转换、清理时保留捕获。
- 自动验收只允许已标记单元的明确预期异常，核对实际异常类型，并确认后续正常单元完成；不得用全局忽略错误掩盖真实失败。未报错但应报错、或异常类型不符，同样视为失败。
- 练习不能用无条件报错的占位代码阻断运行。检查围绕学习目标，不照抄实现；预测输出题不在待预测语句旁直接写答案，可注明运行后如何核对。

## 环境与执行

- 含 Code 单元的 Notebook 在运行前确认所需内核可用，并按所属技术目录 README.md 准备环境；Python 课程沿用 hands-on-computing Conda 环境。解释器归属只在执行检查时核对，不写成教学单元。纯 Markdown 章节按技术协议运行配套文件。
- 依赖清单使用对应技术的格式并集中到技术目录：pip 依赖使用 requirements.txt，npm 依赖使用 package.json 和锁文件。没有相应依赖就不创建清单，不为每章分散创建同类清单或独立环境。
- Code 单元从空内核自上而下执行，写明必要工作目录与输入文件。涉及服务、模型下载、账号或外部资源时，写明运行条件、资源需求、可能费用及关闭清理方法。
- 随机实验记录种子并说明必要的硬件或后端差异；模型实验注明模型标识与修订版、数据版本、关键参数和评估方法。模拟观察不替代真实服务或模型的验证。
- 保存的输出与执行计数必须来自实际运行。可执行逻辑、依赖、输入或运行条件变化后重新验证，不能把旧输出当作新版本通过的证据。
- 仅修改说明或注释时，核对程序语义未变、注释与已有真实结果一致，可保留仍适用的输出。源码展示、异常回溯、行号或生成内容受改动影响时，重新执行相应示例并保存真实结果，不手工修补输出；不确定是否影响行为时，按代码变更验证。报告实际核对范围，不把保留旧输出称为本轮重跑。
- 只有执行并检查结果后才能报告运行通过；未执行、失败或只检查了部分内容时如实说明。安装、语法检查、文档构建和实验执行分别报告。

## 参考与引用来源规则

- 每个知识点写作前核查直接支持其内容及适用条件的官方或第一方来源，定位到页面、小节、版本、论文页码或源码位置；代码注释中的知识解释同样需要依据，不能凭记忆或推测补写。
- 正文知识点后不放来源链接，统一汇总到篇末。只列实际核查且确实支持本章的资料，不列计划阅读的网站，也不为此下载、复制或另建来源归档。
- 最后一个单元固定为“## 参考与引用来源”，其后不追加代码或练习。一个网站只列一次，合并该站点支持的多个知识点与页面，保留直接链接及必要定位；不能只给首页让读者自行搜索。
- 按实际文档站点分组，不把独立站点混成同一来源；同一托管网站上的不同项目或论文合并在一条记录中，但保留各自名称、位置与用途。涉及多个版本时说明对应关系。
- 摘录或节译明确标识，忠实于来源并遵守授权，不整篇搬运。来源无法核实时暂不写入正式正文，在当次交付说明中指出缺口。

## 章节验收

- 主题和标题层级清楚；头部有简洁的“学习目标：”和“前置知识：”，前置知识写具体概念或操作；讲解与最小代码相邻，小结、练习及参考来源齐全。
- 必需的配套文件位于 scripts/ 对应章节目录，或技术目录协议明确的共享模块、数据目录；头部的路径和用途清单与实际文件一致。代码文件按“配套脚本文件头”标注四项信息，运行命令与正文一致，期望结果与实际运行相符；复用模块的首次讲解与实际源码一致，行为变化后检查受影响的章节。引用可访问，无遗留临时脚本或临时运行产物。
- 段落简短而完整，术语前后一致，总览表的原文名称与中文含义逐项对应，符号首次出现有解释；必要边界与练习指向准确。
- 按七条原则核对教学组合、长短代码注释、每处输出预期、可变结果的表述、命名及分支必要性；正文片段与配套代码一致，预测练习保留思考空间。
- 知识解释及代码注释可追溯到写作前核查的来源；篇末来源按网站去重，链接定位直接支持相应内容。
- 实际输出、预期行为与检查结果明确区分；新增或有执行行为变化的 Notebook 从空内核顺序执行全部 Code 单元，预期报错单元的异常符合说明、后续正常单元完成，练习不主动报错占位；浏览器示例检查实际页面及交互。纯说明或注释修改按“环境与执行”核对，不沿用旧结果宣称本轮执行通过。
- 不含验证记录、内核核对或空单元；交付时报告实际执行范围、结果及未验证事项，不另建 Notebook 验证记录文件。
