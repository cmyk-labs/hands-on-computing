# 项目方案与路线图

`hands-on-computing`（《动手学计算机》）是一套从编程基础逐步走向 AI 工程的计算机实践教程，以“理解原理，动手实践”为教学理念。内容以中文为主，以明确的学习问题、可靠解释、可复现实践和适用边界衡量质量；内容稳定后再考虑英文版本。

本文件保存内容方向和交付顺序，规划不代表已经交付或自动授权实施。协作规则见 [AGENTS.md](../AGENTS.md)，通用阅读入口见[开始使用](START_HERE.md)，环境配置与运行步骤见具体技术目录 README.md，教学写法见 [Notebook 编写协议](notebook-protocol.md)，各技术编程规范随课程目录维护，入口见[已有课程](../paths/README.md#已有课程)。

现有课程修订与后续课程实施统一采用 [Notebook 协议的七条原则](notebook-protocol.md#课程编写的七条原则)，从规划和样章开始落实；技术目录仅补充必要的展示方式与技术要求，不重复维护另一份通用原则。

## 内容组织与学习顺序

完整分类只在[总目录索引](../paths/README.md)维护。正文按“知识领域 → 具体技术或专题 → 主题章节”组织，索引负责导航，综合项目引用对应章节。

AI 原理与应用工程统一归入“AI原理与应用”：从必要的数学、机器学习、深度学习和模型机制，逐步进入模型调用、检索、评估与部署；具体专题可以按需先补前置知识，不要求先学完全部原理。

跨领域内容选择主要归属：通用数据存取与索引归数据库，面向模型的检索与评估归 AI；通用系统机制归计算机系统，CPython、JVM 的实现细节归对应语言；FastAPI、Django、Spring 等框架归 Web 与应用开发。其他位置通过链接引用。

| 内容形式 | 主要学习目标 |
| --- | --- |
| 概念讲解 | 解释定义、机制、区别和适用边界 |
| 入门教程 | 通过最小例子掌握一项用法 |
| 实验 | 控制条件、观察现象、检查结果与限制 |
| 工程案例 | 在明确约束下完成设计、实现、测试和取舍 |

这些是教学侧重点，不另建一套形式目录。章节以一个明确主题为单位，相关知识点可合讲，多个独立学习目标应拆分；文件数量服从学习关系，不为目录对称强行拆章。

学习难度从入门操作、基础解释、进阶实现逐步到工程判断与源码或论文研究。各章只要求与当前目标相关的前置能力，不把高阶机制塞进入门章，也不把“使用高级语法”等同于工程能力。

## Python 与 Java 学习方向

两种语言各自形成从基础到工程应用的路线，先完成基础章节和独立小程序，再扩展高阶专题。下表是覆盖维度，不是固定文件数或待创建的子目录。

| 主题 | Python | Java |
| --- | --- | --- |
| 基础语法 | 类型、表达式、控制流、函数、常用容器、模块、异常、文件 | 类型、表达式、控制流、方法、数组、类、包、异常、文件 |
| 语言特性 | 解包、推导式、闭包、装饰器、迭代器、生成器、上下文管理器、类型标注、模式匹配 | 重载、泛型、枚举、注解、Lambda、方法引用、Stream、Optional、record、模式匹配 |
| 对象模型 | 可变性、身份与相等、属性查找、特殊方法、继承、MRO、描述器、元类 | 引用与相等、封装、继承、接口、多态、重写、equals/hashCode、不可变对象 |
| 并发 | 线程、进程、async/await、任务取消、同步与共享状态 | 线程、同步、锁、原子类、线程池、Future/CompletableFuture、虚拟线程 |
| 运行机制 | Python 与 CPython、字节码、对象内存、垃圾回收、GIL 相关行为 | Java 与 JVM、字节码、类加载、运行时内存、GC、JIT、Java 内存模型 |
| 工程工具 | 环境与依赖、打包、测试、调试、日志、性能分析 | JDK、编译与运行、Maven/Gradle、依赖、测试、调试、日志、JVM 诊断 |

标准库按当前用途安排，入门阶段先介绍必要工具，完整用法在后续专题展开；常见误解、边界与工程注意事项就近说明。比较两种语言时链接已有语言章节，不复制讲解，也不要求特性逐项对称。

Python 沿用项目的 3.12 基线；Java 在正式开展时确定稳定基线。涉及版本或实现差异时标注适用条件，核查对应版本的一手资料；预览与实验特性单独说明，不进入默认基础路线。具体章节内容以写作时核查的来源为准。

| 路线 | 主线 | 阶段成果 |

### 样板与检索实践

样板考虑文件处理、数据库索引、向量相似度，分别检查入门讲解、工程实验与数学观察的写法，并补充语言章样板。仍缺先修章节时说明依赖，不将几个样板宣称为完整入门课程。

以下是检索实践专题的内容顺序，可复用对应领域已有章节，不能代替完整语言路线：

| 顺序 | 内容 | 主要产出 |
| --- | --- | --- |
| 1 | 文件、路径与终端 | 定位数据并正确执行命令 |
| 2 | Python 环境与 Git 基础 | 检出指定版本、安装依赖、记录修改 |
| 3 | Python 基本语法与文件处理 | 用函数、循环与数据结构处理小文件 |
| 4 | 数据清洗与可重复输入 | 小型文档数据集与测试样例 |
| 5 | SQL 与数据存取 | 存取文档并理解查询结果 |
| 6 | 数据库索引实验 | 比较查询计划、性能与代价 |
| 7 | 向量、点积与相似度 | 用小数据手算并核对排序 |
| 8 | 关键词与向量检索 | 建立基线、比较适用条件 |
| 9 | 检索评估与失败分析 | 固定查询集、指标和错误分析 |

计划中的首版综合项目为小型文档检索服务，在实际开发时建立 projects/document-search/。基础版使用自制小数据和本地检索，包含关键词基线、向量比较、评估集、HTTP 接口与正确性测试，不要求模型账号。

后续按需引入预训练嵌入、生成模型、RAG、权限、缓存与监控，并注明下载、资源和费用条件；尚未接入生成模型的检索服务不命名为 RAG 项目。

## 实验与综合项目

教学 Notebook 的执行要求以编写协议为准。综合项目保留目标与约束、相关章节、架构和决策、运行与清理、测试和评估、限制与复盘；项目说明不重写全部基础原理。

| 项目说明 | 必要内容 |
| --- | --- |
| 环境与输入 | 工作目录、操作系统、语言和关键依赖版本、数据来源与版本；未验证的平台不宣称支持 |
| 资源与外部条件 | CPU/GPU、内存或显存、预计时间，以及下载、网络、账号、密钥和可能费用 |
| 运行与检查 | 从干净检出到结果的命令、成功标准、必要断言、常见错误和排查方法 |
| 实验设计 | 基线、变化条件、观察指标及限制；不预设跑分或将模拟结果当作真实效果 |
| 清理与复现 | 服务关闭、资源清理、对应代码版本与稳定里程碑，确保读者能重建相同行为 |
| 验证记录 | 综合项目保存简短记录，注明被验证的代码提交、环境、命令、时间、实际结果与已知限制 |

轻量入门实验优先小数据、CPU 和无需付费凭据的路径。随机实验记录种子，模型实验记录模型与数据版本、关键参数和评估方法；必要时说明硬件或后端差异。大型数据、权重、缓存、密钥和完整服务日志不进入普通 Git 提交。

内容成熟度与实验状态分别判断：排版完成不代表实验通过；执行行为变化后须重新验证，仅改说明或注释时按 Notebook 协议核对已有结果是否仍适用，不把已有输出核对称为本轮重跑。可自审；重大性能结论或复杂原理优先独立复核。Notebook 的检查结果只在当次交付说明中报告，不另建验证记录。

## 发布与持续维护

- 初期直接阅读 Markdown 和 Notebook，保留可下载、可本地执行的入口；内容稳定后再评估文档网站。Quarto 是待评估选项，采用时锁定构建工具版本，网站构建不隐式触发昂贵实验。
- 自动检查按实际内容逐步增加，先覆盖格式、内部链接和受影响的轻量实验；共享依赖变化后扩大检查范围，定期复查外部来源与运行条件。当前不建立额外元数据体系或复杂课程平台。
- 来自外部贡献的自动检查默认不使用凭据；真实服务、GPU、付费 API、大数据和长时间任务按明确任务范围触发。文档构建与实验运行分别报告。
- 首批样板完成后，邀请未参与编写的读者准备环境、运行样例、解释结果并修改一个参数，优先修复卡住的位置，再扩展内容。
- 贡献以内容纠错、运行问题和选题建议为起点；同一时间控制在写章节数量，不另设日志目录。原创教程与代码采用 [CC BY-NC-SA 4.0](../LICENSE)，署名 CMYK Labs（cmyk-labs），第三方材料单独核实授权。
