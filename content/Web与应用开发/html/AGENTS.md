# HTML 教学写作补充协议

## 适用范围

适用于本目录及子目录中的 HTML 教学 Notebook、配套页面和资源。修改前读取[项目协作协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及本文件；本文件集中维护 HTML 教学写作与检查要求，其他要求沿用通用协议，用户最新明确要求优先。

普通工程标记参考 [HTML 编程规范](HTML编程规范.md)，配套样式见 [CSS 编程规范](../css/CSS编程规范.md)，辅助 Python 脚本参考 [Python 编程规范](../../编程语言/python/Python编程规范.md)。课程固定路径写成一个完整相对字符串，有变量时只连接完整固定后缀。教学中为解释机制而采用的其他写法或明确反例可以保留；最小片段不强制套用完整工程结构，既有代码不要求批量格式化。

章节范围以 [plan.md](plan.md) 为准。学习目标、前置知识、小结、练习和篇末引用沿用通用结构；本文件不重复模板，也不将某次审核发现或单章示例固化为全课程要求。

## 知识依据与术语

- HTML 元素语义、属性和约束依据 [WHATWG HTML Living Standard](https://html.spec.whatwg.org/multipage/)；URL 组成与解析依据 [WHATWG URL Standard](https://url.spec.whatwg.org/)；可访问性依据 [W3C WAI](https://www.w3.org/WAI/tutorials/)。写作时进一步定位到直接支持知识点的具体小节，不能仅引用这些入口页。
- 教学组织可参考 [MDN HTML 课程](https://developer.mozilla.org/en-US/curriculum/core/semantic-html/)，解释和用例可对照 MDN；规范性结论回到对应标准，平台与浏览器差异核查厂商文档。菜鸟教程等可借鉴简洁呈现方式，不整篇搬运，也不作为语言规则的唯一依据。
- 正文与代码注释逐点核查来源及适用条件，区分标准要求、浏览器默认行为和本例约定。兼容性相关结论注明必要的浏览器与版本条件；一次运行结果不能代替标准依据。引用按通用协议集中在篇末，不另建来源记录文件。
- 采用通行术语，易歧义者首次附英文并简述含义；标签名、属性名、属性值和 API 保留原文。URL 方案（scheme）、基准 URL（base URL）等名称前后一致，不为了中文化另造词。
- 分清标签、元素、属性与属性值，全局属性说明适用范围。相关概念容易混淆时就地用一句话区分，例如 URL 的百分号编码与 HTML 字符引用，不让读者凭相似写法猜测含义。

## 知识覆盖与学习顺序

- 对照章节规划与对应标准检查基本用法、必要条件和常见边界。覆盖范围以本章学习目标为准；不遗漏完成目标必需的知识，也不为穷举所有元素、属性或 API 扩张章节。
- 先讲用途和最常用写法，再讲相关机制与例外。查询参数、编码等内容分步引入，综合示例安排在所用基础概念之后。
- 次要或进阶内容明确标为补充，不能成为理解基础示例的隐含前提。跨章内容只简述当前所需用途并链接已有章节，不复制完整讲解。
- 易错点与工程注意紧邻对应知识点。涉及链接、图像、表单和交互时，保留当前用法必要的语义、可访问性与兼容条件，不为简短而删除关键限制。

## 正文组织与排版

- 按“简短说明 → 最小 HTML 示例 → 配套文件与浏览器入口”组织，每节围绕一个明确用途。段落按意思分开，不堆密集长文，也不把每句话机械拆成条目。
- HTML Notebook 教学正文仅标签总览使用说明表格，列出“标签、中文名称／含义、用途”，每个标签独立一行；需要时增加最小写法。教学中的数据表格示例仍可正常使用 HTML 表格。独立编程规范文档按工程说明需要使用表格。
- 标签总览及其他文字中的标签写完整，如 &lt;a&gt;、&lt;base&gt;。Notebook 正文用字符引用转义尖括号，避免被当作 HTML 渲染；代码块内保留原样，不用裸 a、base 代替标签。
- 标签、属性和属性值分开介绍。属性、属性值、URL 组成、路径及排错等并列说明使用 Markdown 无序列表，以 - 起行；每项写清名称和含义，列表与前后段落用空行分隔。简单说明保留短段落。
- 表格说明用途，正文补充用法与必要条件，相邻代码注释写明预期效果与必要的观察重点；三者不重复复述。删除写作流程、重复导语和无实际帮助的提醒，保留读者理解代码所需的解释。

## 最小示例与解释尺度

- 每例突出一个观察目的，优先使用几行直接的 HTML，不机械限定行数。基本写法不要同时叠加多个尚未介绍的属性、编码或脚本行为。
- 比较示例尽量保持其他条件一致，只改变正在讲解的条件。需要视觉分开的链接或控件用 &lt;p&gt;、列表等合适结构分开，不能依靠源码换行让读者区分显示结果。
- 首次出现的属性值、符号、自定名称和路径就地说明；结果有条件时写清条件。解释应补足代码看不出的原因，不逐行翻译源码。复杂的路径解析可用简短目录树和实际目标地址辅助理解。
- 预期行为和检查方法写进对应 HTML 注释，不再另加重复的结果说明段落。练习提供明确任务与可观察结果，提示与题目分开，不在题目旁直接展开答案。

## Notebook 与配套页面

- 辅助学习示意图放在 `image/illustration/`，实际成图与截图放在 `image/`；Notebook 图形输出不要求另存。制作、编号、扩展名与跨章复用遵循[通用图示要求](../../../docs/notebook-protocol.md#图示的制作与整合)。
- Notebook 是唯一教学正文。HTML 片段放在带 html 语言标记的 Markdown 代码块中，完整页面及必要资源按需保存在 scripts/章节/，如 scripts/06-links-and-urls/；头部按通用协议列明文件、路径和用途。
- 配套页面文件头按通用协议用紧随 doctype 的 &lt;!-- --&gt; 注释块标注四项信息，期望结果只写一句话要点；各处预期效果写在相邻代码注释中。整个页面的多步操作与检查顺序可集中在文末注释，不用文末说明替代各处预期，也不重复复述。
- 展示 HTML 不加入 %%html、%%writefile 或 Python 包装代码。片段须与所指配套文件一致，不要求读者先运行文件生成代码才能看到页面。
- 完整页面保留运行所需结构，Notebook 只展示当前解释所需的片段并标明所属文件。讲文档结构时展示完整结构；不要为缩短代码隐去当前知识点必需的上下文。
- CSS 与 JavaScript 只在本节确有需要时作为辅助，简述作用；HTML 主线示例不要求读者先理解大量样式或脚本。观察器的额外字段按需展示，不让调试信息占据主要阅读区域。

## 路径与运行入口

- 环境准备链接到本目录 README.md，浏览器与 Python 辅助服务的条件分别说明；安装步骤集中维护。章节用 Step 短步骤保留服务命令、工作目录、页面入口和停止方式，专用服务按本章实际需要说明。
- Notebook 的配套文件链接相对于 Notebook；HTML 中的相对 URL 按配套页面的基准 URL 解析。涉及路径时说明起点，区分磁盘目录、HTTP 服务根目录与页面地址；基准改变时同步解释受影响的示例。
- 在开篇一次写清本地服务的工作目录、启动命令、浏览器入口和停止方式；各节提供准确的配套文件链接与必要的预览入口，不重复启动说明。演示绝对 URL 或确有外部目标时，保留相应完整 URL。
- 移动或改名文件后同步检查头部、正文链接、页面内引用和服务地址，不以文件存在代替 URL 正确。配套页面保留为教学资源，临时预览和检查产物用后清理，不在 Notebook 旁另留重复正文。

## 检查与交付

- 检查术语一致性、章节覆盖、来源条件和示例上下文；基础内容缺失时不得仅凭目录或引用列表判定完整，也不宣称穷尽全部知识点。
- 检查 Notebook 渲染、标签显示、源码与配套文件一致性，以及从实际服务根目录访问的资源路径。确认列表、代码和段落之间的分隔正常。
- 在真实浏览器中检查本次改动涉及的跳转、片段定位、下载、窗口、表单等行为，按示例需要检查键盘操作。区分正常示例与明确标注的反例；记录实际检查范围，不能把文档渲染或资源返回成功等同于交互通过。
- 只有 Markdown 的章节无需内核执行计数和输出；若有需要内核运行的 Code 单元，仍按通用协议从空内核执行并保存真实输出。检查结果和未验证事项仅写在交付说明中，正文不增加验证记录或核对内核。
