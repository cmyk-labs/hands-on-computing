# CSS 教学写作补充协议

## 适用范围

适用于本目录及子目录中的 CSS 教学 Notebook、配套页面、样式和资源。修改前读取[项目协作协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及本文件；环境配置见本目录 README.md，CSS 专属写作与检查要求集中维护在这里。

普通工程样式参考 [CSS 编程规范](CSS编程规范.md)，页面结构见 [HTML 编程规范](../html/HTML编程规范.md)，辅助 Python 脚本参考 [Python 编程规范](../../编程语言/python/Python编程规范.md)。课程固定路径写成一个完整相对字符串，有变量时只连接完整固定后缀。教学中为解释机制而采用的其他写法或明确反例可以保留；最小片段不强制套用分层或抽象，既有代码不要求批量格式化。

章节范围以 [plan.md](plan.md) 为准。先完成用户指定的样章供其确认，再按授权范围展开后续章节；不将一次检查结果或单章例子写成全课程要求。

## 知识依据与术语

- 语言规则依据 [W3C CSS 规范](https://www.w3.org/Style/CSS/specs.en.html)中的对应模块，HTML 集成依据 WHATWG HTML 标准；写作前定位到直接支持知识点的具体小节。MDN 可用于教学组织、用法和兼容性核查，浏览器行为及工具操作参考厂商文档。
- 区分规范规则、浏览器实现、默认样式和本例约定。CSS 按模块演进，不用“CSS3”笼统代表所有现代特性；对新特性注明必要的规范状态、支持条件及回退方式。
- 使用通行术语，易歧义或译法不统一者首次附英文并简述含义；不强求唯一中文译法。属性、选择器、函数、单位、关键字、描述符及 @ 规则保留完整名称，不省略属性前缀。
- 分清 HTML 属性（attribute）、CSS 属性（property）、属性值、选择器、@ 规则和描述符（descriptor）。同形名称或跨章概念容易混淆时，用一句话说明区别及本章侧重点。
- 知识解释和代码注释都须有已核查的第一方依据；引用集中在篇末，按网站合并并保留具体定位。实际观察不能代替规范依据，不另建来源记录文件。

## 知识覆盖与学习顺序

- 以章节目标检查基本用法、必要条件和常见边界；不把全部属性参考搬进课程，也不因规划采用概括名称就判定正文遗漏。
- 先展示具体用途与最小写法，再展开机制。前面尚未介绍的选择器、单位或布局条件，只补足当前例子所需说明；后续系统章节不重复整段讲解。
- 层叠、继承、外边距折叠、包含块、层叠上下文、Flexbox 和 Grid 等机制需要解释成立条件和原因，不能压缩成属性记忆表。用逐步变化的小例子控制信息量。
- 次要和进阶内容明确定位为补充。复杂作用域规则、完整算法、工程工具或兼容策略不成为基础示例的隐含前提。
- 易错点和工程注意紧邻对应示例。涉及视觉顺序、焦点、隐藏、颜色和动画时，保留必要的阅读顺序、键盘、对比度与用户偏好说明，不为简短删除关键条件。

## 正文组织与排版

- 按“简短说明 → 必要的 HTML → 最小 CSS 示例 → 配套文件与浏览器入口”组织。一个小节围绕一个用途或观察目标，段落按意思分开；不要堆长文，也不要逐句机械列项。
- Notebook 教学正文需要总览时只用属性总览表，列“完整属性名、中文名称／含义、用途”，按需增加作用对象；每个属性一行。Flexbox、Grid 等区分容器属性和项目属性，不把选择器、属性值、描述符或 HTML 标签混入同一属性表。独立编程规范文档按工程说明需要使用表格。
- 选择器、属性值、单位、@ 规则、描述符、路径和排错说明用短段落或以 - 起行的列表。例子先给完整写法，首次出现的符号、数值、类名和路径就地解释。
- 引用 HTML 标签时写完整并转义尖括号，如 &lt;p&gt;；CSS 选择器 p 则保留合法 CSS 写法，并说明它选择 &lt;p&gt; 元素。代码块内保留原样。
- 总览说明用途，正文解释用法和条件，相邻代码注释标明预期效果与必要的观察重点；三者不重复复述。删除写作流程、重复导语和逐行翻译代码的说明。

## Notebook 与最小示例

- Notebook 是唯一教学正文。CSS 与 HTML 使用带 css、html 语言标记的 Markdown 代码块；不为显示样式加入 Python 包装、%%html、%%writefile 或要求读者先生成页面。
- 配套文件按需放在 scripts/二位序号-英文主题/，例如 scripts/01-stylesheets-and-syntax/。头部按通用协议写“配套脚本：”并列出页面、样式和资源的路径及用途；不创建无用途的占位文件。
- 配套样式文件头按通用协议用 /* */ 注释块标注四项信息；页面文件的文件头按 HTML 补充协议写在 doctype 之后。
- 片段须与所指文件一致。HTML 保留观察所需元素和结构，CSS 保留影响结果的必要规则；不以省略上下文换取短代码。完整页面保留文档结构，正文只展示当前所需片段。
- 比较示例尽量保持 HTML 和其他条件相同，只改变当前讲解的 CSS 条件；可使用并列例子或独立页面。辅助样式不得掩盖默认行为、改变实验前提或引入未解释的布局机制。
- 默认不引入框架、构建工具或 JavaScript；确有需要时说明其辅助作用，保留原生 CSS 的可读性。练习让读者修改少量规则并观察变化，不在题目旁直接展开答案。
- 预期行为与检查重点写进相应 CSS 或 HTML 注释，不在代码后重复写结果段落。涉及尺寸和颜色时结合开发者工具观察，不只凭截图或肉眼判断。

## 路径与浏览器运行

- 环境准备链接到本目录 README.md，Notebook 阅读工具与页面运行条件分别说明；章节用 Step 短步骤提供实际服务命令与页面入口，保留影响示例的浏览器支持和视口条件。
- 区分 Notebook 链接、HTML 资源链接和 CSS 内的相对 URL。外部样式表中的相对 URL 以样式表 URL 为基准；内嵌样式按所在文档的基准 URL 解析。路径实例写清起点，必要时给简短目录树。
- 在开篇一次写明服务工作目录、启动命令、浏览器入口与停止方法；各节给准确的配套文件和必要的预览入口，不重复启动说明。
- 修改后保存源文件并刷新页面；开发者工具的临时修改与源文件修改要分清。移动文件后同步检查引用、导入、资源地址及服务入口。

## 检查与交付

- 检查章节目标、术语、来源条件、正文渲染、代码片段与配套文件一致性，以及本地路径和 HTTP 资源加载。
- 在真实浏览器中检查本次涉及的生效样式、计算样式及视觉效果；按例子需要检查视口变化、键盘状态和交互。语法可解析、资源返回成功或截图生成不等于效果正确。
- 分清无效声明、有效但未生效的声明，以及明确标注的反例。检查应确认预期差异，不能将错误全部忽略后报告通过。
- 只有 Markdown 的章节无需内核执行计数和输出；如确有 Code 单元，沿用通用协议的执行要求。检查结果和未验证平台只写在交付说明中，不在正文增加验证记录、核对内核或环境打印单元。
- 保留教学所需文件，及时清理临时预览、检查脚本和运行产物；不在 Notebook 旁另留一份 HTML 正文。
