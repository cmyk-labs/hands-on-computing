# CSS 编程规范

第 2 版 · 来源核查日期：2026-09-13

面向普通网站、应用界面和可复用样式，覆盖层叠、选择器、布局、响应式、无障碍、资源、组织、验证及维护。前置知识是 HTML、选择器、声明和盒模型。示例使用原生 CSS；框架、预处理器和特定设计系统按项目需要选择。

本文依据 W3C／CSSWG 模块规范、WCAG、WAI 和维护者指南，进行中文选编与工程整理。**平台约束**说明 CSS 实际行为；**风格选择**用于团队一致；**工程建议**按界面和交付条件采用。CSS 各模块有独立版本与标准化状态，不能把所有新特性统称为一个已经普遍支持的“CSS3”。

## 1 依据与兼容范围

### CSS-01 同时核对规范和目标浏览器

规范定义属性含义，浏览器实现决定实际可用性。项目记录支持的浏览器范围和本次实测版本，使用新选择器、函数、查询或布局能力时检查目标环境；开发者工具认识某属性不代表所有使用者都支持。

选择稳定且满足业务的能力，不为展示新语法强行增加依赖。需要兼容较旧环境时，设计可用的基础样式，并明确增强部分的条件。

### CSS-02 区分规则、风格和设计参数

缩进、类名风格、声明分组与断点数值属于项目约定；颜色、间距、圆角和字体属于设计选择。本文选取 Google HTML/CSS Guide 的可读性建议，不把其全部历史写法强制套用到现代项目。

**工程整理：** 修改围绕实际问题，不用样式文件行数、选择器数量或是否使用某框架评判质量。已有清楚的简单布局可以保留。

## 2 格式与命名

### CSS-03 统一可自动检查的格式

可采用 2 空格缩进、每条声明独占一行、声明末尾分号、选择器组分行以及规则间空行。属性名和普通关键字通常用小写；自定义属性名称的大小写有意义，不随意改写。

Prettier 等工具负责格式；Stylelint 按明确配置发现无效值、重复声明和可疑写法。声明顺序可以按项目的逻辑分组或其他一致约定，不让格式规则覆盖有意安排的后备声明。

### CSS-04 名称说明组件或职责

类名使用能说明角色的名称，如 `.reading-card`、`.page-header`。BEM、CSS Modules、工具类或其他方案按项目选择，不规定所有项目必须采用同一种命名法。

语义状态优先对应真实属性，例如 `[aria-pressed='true']`、`details[open]`；普通业务状态可以用明确的类或 `data-*`。不要只用颜色名命名会随主题变化的业务组件，也不要让一套复杂 DOM 路径成为样式接口。

## 3 层叠与选择器

### CSS-05 理解完整层叠关系

层叠不只是“后写的覆盖先写的”。来源、重要性、层等条件先参与排序，然后才比较选择器特异性及同等条件下的声明顺序；继承也不是与所有显式声明按同一优先级竞争。

在开发者工具中检查实际获胜声明，再调整选择器或组织结构。避免不断提高特异性或添加 `!important` 掩盖错误；确有外部样式覆盖等需求时，局部说明原因和边界。

### CSS-06 用层和低特异性控制扩展成本

项目可以显式声明 `@layer reset, tokens, base, layout, components, utilities;`，让职责顺序可见。在同一来源的普通声明中，后声明的层高于先声明的层，未分层的普通声明又高于分层声明；重要声明的层顺序相反。

`:where()` 自身及其参数不增加特异性，适合低权重基础选择器。避免依赖 ID 选择器或过深嵌套来控制常规组件；CSS 层不是安全边界，也不代替对外部样式的检查。

## 4 值、变量与设计约定

### CSS-07 把共同设计值集中维护

复用的颜色、间距或尺寸可以定义为自定义属性，按含义命名，例如 `--color-text`、`--space-section`。只出现一次且容易理解的值不必全部变量化，也不为每个声明制造一层别名。

自定义属性参与层叠并通常继承；`var()` 后备值只处理相应变量缺失或无效等情况，不能保证替换后一定符合目标属性的语法。主题切换优先改变共同变量，避免复制整套组件规则。

### CSS-08 按含义选择单位和尺寸

字体与可缩放间距可用 `rem`、`em`；百分比、视口单位和容器单位要清楚其参照对象。像素适用于有明确视觉边界的细线等场景，不能把“禁止 px”当作无障碍规范。

`min()`、`max()`、`clamp()` 用于有上下界的连续变化；文字大小需要保留用户放大后的可读性。纯视口字体不能自动保证文字缩放需求。零长度是否省单位按语法和团队约定处理，不把所有零值都一律改写。

## 5 盒模型与布局

### CSS-09 让盒子适应真实内容

明确使用 `content-box` 还是 `border-box`，基础层可以统一设置 `box-sizing`。边框与内边距是否计入声明尺寸取决于该属性；不要靠反复减像素修补不了解的盒模型。

避免对承载可变文字的容器设置会截断内容的固定高度。长标题、长链接、翻译和空内容都要检查；按需要使用 `min-inline-size: 0`、`overflow-wrap` 等让内容收缩或换行。确需裁剪时提供取得完整信息的方式。

### CSS-10 选择布局机制并保留阅读顺序

一维对齐可用 Flexbox，二维行列可用 Grid，普通文流能完成时也可直接使用。绝对定位适用于明确的叠放关系，不宜作为整个页面排版的默认机制。

视觉重排不应破坏 DOM 阅读和键盘顺序。不要用 `order` 或网格位置隐藏错误的文档结构；使用定位和 `z-index` 时注意层叠上下文，数值更大不代表能越过任何祖先边界。

## 6 响应式与渐进增强

### CSS-11 由内容决定断点

基础样式先保证窄屏可用，再按内容拥挤或阅读需求增加断点。可用 `minmax()`、`auto-fit` 和弹性布局减少不必要的断点；不要仅按某几个设备型号硬编码完整页面尺寸。

媒体查询面向视口或用户环境。组件随其所在区域变化时，可在合适的祖先建立查询容器，再用容器查询增强。需要尺寸包含的属性可能改变布局计算，应在目标布局中实测，保留不支持时的基础呈现。

### CSS-12 新能力提供可用后备

`@supports` 可以测试浏览器是否接受特定声明或条件，再应用增强样式；它不证明渲染没有实现缺陷，也不自动提供 polyfill。后备布局本身应保留内容与操作。

浏览器忽略不支持的声明时，应仍有合理的已有声明可用。引入嵌套、容器查询或其他新能力后，更新兼容范围与验证用例，不靠盲目增加前缀代替调查。

## 7 文字与颜色

### CSS-13 排版支持阅读与缩放

使用合适的字体后备和可读的行高，限制正文行长，并使段落间距表达结构。中文、英文、长标识符和不同字体度量可能有不同换行结果，不用固定高度假定每行恒定占位。

检查文字放大和用户覆盖行高、字间距后的内容。WCAG 2.2 的文字缩放和文本间距条款有明确适用范围；不能因为默认字号看起来够大就省略相关验证。

### CSS-14 核对对比度并保留非颜色提示

以 WCAG 2.2 AA 为目标时，一般文字对比度至少 4.5:1，符合原文定义的大号文字至少 3:1；非活动控件、标识等有例外。可识别控件和必要图形的非文本对比要求按相应条款检查，不把同一数值套用所有装饰线条。

状态同时使用文本、形状或其他可理解提示，避免仅靠颜色区分成功和失败。深色主题、悬停、焦点和禁用等状态分别评估；降低整体透明度可能同时降低文字对比。

## 8 交互与无障碍

### CSS-15 让键盘焦点可见且可到达

保留浏览器默认焦点，或用同样清楚的样式替代；可用 `:focus-visible` 针对键盘等需要焦点提示的情况增强。悬停效果应有适当的键盘对应状态，不能只在 hover 时暴露必要操作。

检查固定页头、弹层和裁剪是否遮住焦点。目标大小参考 WCAG 2.2 的相应级别和例外；24 CSS 像素的最小目标条款不能误写成所有行内链接一律固定宽高。

### CSS-16 区分隐藏、不可见和不可操作

`display: none`、`visibility: hidden` 与只做视觉隐藏的技术效果不同。屏幕阅读器需要的说明不能随意用 `display: none` 移除；视觉隐藏也不能让仍可聚焦的控件落到使用者看不到的位置。

样式层不负责权限控制；隐藏按钮、遮挡文字或 `pointer-events: none` 不会自动禁止键盘操作或服务端访问。真实禁用、展开和选择状态由语义 HTML 与行为代码维护。

## 9 用户偏好与打印

### CSS-17 尊重主题和强制颜色

用 `prefers-color-scheme` 响应系统偏好；提供手动选择时明确它与系统偏好的优先级。`color-scheme` 可影响浏览器绘制的原生控件及其他界面部分，需要与自定义背景和文字协调。

强制颜色模式下优先让浏览器调整颜色，必要时使用系统颜色和边框保持可识别性。慎用 `forced-color-adjust: none`，不要为了保留品牌色破坏用户需要的对比方式。

### CSS-18 动效与打印各有用途

动效应服务状态反馈，过渡只列出实际需要变化的属性，避免随意使用 `transition: all`。对 `prefers-reduced-motion: reduce` 提供减少或关闭非必要运动的方案；不要用闪烁或强制自动运动传递唯一信息。

需要纸面阅读的页面提供打印样式：保留标题、正文和关键信息，按需隐藏纯操作控件，处理背景和分页。打印媒体模拟能验证样式条件，实际纸张分页或导出 PDF 的结果仍需对应检查。

## 10 资源与边界

### CSS-19 控制资源成本和失败后表现

图片、字体和背景资源应有实际用途，路径相对所属文件明确。图片尺寸约束与 `aspect-ratio` 可帮助保持布局；字体不可用时后备字体仍应可读。不要仅为了示例外观依赖不稳定的远程资源。

性能改动先测实际页面，再定位样式计算、布局、绘制或资源问题。合成、包含和懒呈现等优化都有适用条件，不把某个属性写成永远更快的技巧。

### CSS-20 不把样式当作可信内容容器

不把敏感数据放进选择器、资源 URL 或生成内容；CSS 随页面交付，隐藏内容并不提供保密能力。接受外部主题值时按允许的属性和值域处理，不能直接拼接整段未经评估的 CSS。

关键文字和操作名称保留在 HTML，伪元素适合装饰或可冗余的信息。样式表更新不能代替表单校验、权限控制或安全的 DOM 文本插入。

## 11 工程组织与验证

### CSS-21 按实际职责组织样式

可以按基础、设计变量、布局、组件、工具层组织；小项目保留一份分区清楚的文件也合理。不要为了每个选择器一个文件引入无收益的加载和跳转成本。组件样式的复用依据是真实共享行为。

需要开发工具时保存 `package.json` 与锁文件，本地和 CI 共用格式、Stylelint、HTML 结构及浏览器测试入口。没有构建需求就直接交付 CSS；不能把使用预处理器作为工程合格的必要条件。

**工程建议：** 长期使用第三方样式包、插件或构建工具时，定期检查已知漏洞与安全公告，按使用方式评估影响。npm 依赖可用 `npm audit` 辅助检查，修复先评估兼容性；升级后同步清单与锁文件，复查受影响的输出样式、布局和资源加载。

### CSS-22 测试实际布局和交互

检查窄屏、宽屏、长内容、空内容、缩放、键盘焦点、主题、减少动效、强制颜色和打印等适用状态。正常纵向阅读页面按 WCAG 重排条件检查相当于 320 CSS 像素宽度的呈现；必须二维布局的内容有例外。

浏览器测试可检查溢出、可见性、计算样式和操作结果，并保留代表性截图作人工检查。自动无障碍扫描只能发现部分问题，不能据此声明整个页面符合 WCAG；需要时另做辅助技术和多引擎实测。

## 12 交付与维护

### CSS-23 检查使用者取得的文件

静态交付应确认 HTML 引用的样式和资源实际存在，路径、内容类型与浏览器加载结果正确。若有打包或压缩，测试输出目录中的真实产物，并保留合理的调试来源。

记录实际浏览器、工具版本、工作目录、运行及关闭方式。安装成功、语法或格式通过、浏览器运行和人工视觉检查分别报告，不沿用变更前的截图宣称变更后通过。

### CSS-24 维护样式接口和变更范围

公共类名、自定义属性、主题接口和重要布局行为属于可复用样式的使用契约。删除或改变时评估调用方影响，在发布说明中说明迁移方式；独立样式包按项目选择的版本策略维护。

**工程整理：** 每项规则可对应实现、测试或明确的条件选择。没有主题服务、用户样式上传或印刷交付时，不为展示规范额外建立这些系统。现有清楚的代码按实际收益优化，避免只为追求形式统一扩大改动。
