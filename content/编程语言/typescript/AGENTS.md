# TypeScript 教学写作补充协议

## 适用范围

适用于本目录及子目录中的 TypeScript 教学 Notebook、源码、类型声明、配置与配套资源。修改前读取[项目协作协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及本文件。章节范围与版本基线以 [plan.md](plan.md) 为准，通用结构沿用上级协议。

正常工程代码参考本目录可独立阅读的 [TypeScript 编程规范](TypeScript编程规范.md)。Notebook 可以为明确的教学目的展示其他写法和反例；最小入门片段不强制增加抽象、类型标注或程序入口，也不要求批量重排既有代码。教学组织与实际检查仍按以下要求执行。

## 知识依据与术语

- 以 TypeScript 官方 Handbook、Reference、TSConfig Reference、发布说明及必要的官方源码为依据；工程工具和宿主行为分别查其官方文档。规划中的“规划依据”用于定位主题，正文写作前仍逐点核查具体小节、编译器版本与配置。
- 使用通行术语；类型收窄（narrowing）、结构类型（structural typing）、可辨识联合（discriminated union）、映射类型（mapped type）、条件类型（conditional type）、模块扩充（module augmentation）等首次附英文并简述含义。译法不一致时保留英文，不创造新的机制名称。
- 区分类型与值、类型参数与类型实参、类型推断与类型断言、泛型约束与条件类型判断、类型守卫与类型谓词。T、K、P 等在首次使用处说明所代表的类型或键，不让读者猜测符号。
- 不把 TypeScript 类型系统描述为保证所有运行时行为正确的机制。类型断言、非空断言、readonly、declare、private 等分别说明检查范围与运行语义；不能把它们笼统等同于数据转换、运行时校验、冻结或 JavaScript 私有元素。
- 旧式装饰器与 TypeScript 5.0 起支持的装饰器语义分开；弃用选项、版本新增行为和提案状态明确标记。当前不支持的旧例仅用于阅读或迁移，不混入默认通过的主线项目。
- 来源集中到 Notebook 篇末并保留具体定位；真实诊断不替代权威解释，不另建来源档案，不宣称覆盖全部编译器内部规则及第三方生态。

## 教学组织与解释尺度

- 默认读者已有相应 JavaScript 基础。按“具体需求 → 最小类型写法 → 必要的检查解释”组织，先展示正常用法，再按需给出错误例子与修正；不重复完整的循环、闭包、Promise 或 DOM 课程。
- 一个例子突出一个类型关系。泛型从保留输入与输出关系引入，条件类型从具体分支引入；先解释约束、推断及条件，再组合使用，不把复杂类型运算题作为主线。
- 类型收窄、可赋值性、结构类型、泛型约束、声明与模块解析须解释成立条件。关键错误指出位置、相关类型及失败原因，不只写“报错”或用大量诊断文本代替解释。
- 同类类型、工具类型或编译选项可使用“完整名称、中文名称／含义、用途”总览表，每项一行；类型运算符、运行时 API、声明和编译选项不混表。推断步骤、边界与路径用短段落或以 - 起行的列表。
- 正确示例优先利用推断与收窄，不无故给每个变量加标注。any、断言、非空断言、@ts-ignore 和 skipLibCheck 的使用必须有当前例子的理由，不以取消检查解决教学示例中的类型问题。
- 预期类型、诊断与运行输出写在相应代码注释中，必要解释放在代码前，不在代码后追加重复结果段落。纯类型示例可以没有运行输出；表格、正文和注释不重复复述。Notebook 正文不使用反引号行内高亮。
- 工程注意紧邻知识点；类型检查不能代替外部输入校验，编译器认识某个 API 不能代替宿主提供其实现。涉及高级类型时保留可维护性与检查成本的必要说明，不以复杂度代表教学深度。

## Notebook 与配套文件

- Notebook 是唯一教学正文。TypeScript 使用带 typescript 语言标记的 Markdown 代码块，JSX 示例使用 tsx，JavaScript、JSON 和命令分别使用对应标记；不添加 Python 包装或文件生成魔法命令。
- 头部沿用学习目标、具体前置知识及“配套脚本：”要求，列出 scripts/二位序号-英文主题/ 下的源码、配置或声明文件及用途。给出从技术目录出发的检查命令，相关小例子可放在同一文件，不机械拆分文件。
- 片段与配套文件一致，保留类型定义、导入、输入和影响检查结果的选项。每个示例有明确的编译项目范围，不能依赖其他章节意外合并的全局声明；模块示例与全局脚本示例分别组织。
- 类型检查、代码生成、运行三个步骤按需要提供。只有类型声明的例子只做相应静态检查；涉及枚举、参数属性、装饰器、导入或其他输出差异时，同时检查生成代码及其运行结果。
- 默认使用项目内 TypeScript 编译器和 Node.js；仅在浏览器、JSX 或框架类型确有需要时添加配套页面或依赖，并解释辅助作用。JavaScript 基础的运行规则引用已有内容，不复制正文。

## 编译配置与路径

- 完整工具版本、安装步骤与运行入口集中在本目录 README.md；章节头部链接该入口，保留影响检查的版本与配置条件。编辑器使用与命令行匹配的版本；升级后重新核查诊断、输出和工具兼容。
- 使用本技术目录的 package.json 与锁文件维护工具和类型依赖，以 npm scripts 调用项目编译器；Notebook 阅读工具按通用入口准备。
- 操作说明采用 Step 短步骤，一步一句话、一个命令；章节分别给出检查、编译和运行命令。首章关于编译器、tsconfig 与类型擦除的教学内容仍完整保留。
- 显式启用 strict；noUncheckedIndexedAccess、exactOptionalPropertyTypes、noImplicitOverride 等附加选项就地说明。比较不同设置时标出差异，不为了让例子通过而悄悄关闭检查。
- 使用 tsc -p 指向明确的项目配置；逐例核对包含哪些文件。区分 target、lib、module、moduleResolution 和宿主支持，说明声明、语法转换与 polyfill 的分工，不能把 paths 当作自动改写运行时导入的工具。
- Node.js 的类型剥离、其他工具的转换与 tsc 类型检查分别验收；能够直接运行 .ts 文件不能作为静态检查通过的依据。涉及编译器 API 的工具还须核查所选版本的兼容条件。
- 课程代码的固定路径使用完整相对路径字符串，有变量时只连接完整固定后缀，例如 new URL("./data/reports/summary.json", import.meta.url)；区分相对配置文件、源模块、输出模块和当前工作目录的路径，核对输出后的导入扩展名与包入口。

## 检查与交付

- 检查章节覆盖、术语、前置关系、引用定位、正文渲染和片段一致性。纯 Markdown Notebook 不要求内核执行计数或输出；如使用 Code 单元，仍按通用协议执行。
- 正常示例使用固定配置实际检查并确认无意外诊断。预期错误用例与正常用例区分，核对错误位置和原因；@ts-expect-error 只确认下一行存在错误，不能单独证明就是预期的错误，需要时核对原始诊断。
- 运行示例核对输出、异常、退出状态及副作用。涉及外部数据的守卫或断言函数用有效、无效及边界输入检查，不能只凭返回类型声明认定实现正确。
- 声明文件和包示例由独立消费者实际检查类型解析，并运行真实安装产物；不让工作区源码或全局依赖掩盖声明、路径或发布文件缺失。
- 检查结果和未验证平台仅在交付说明报告；不在 Notebook 添加验证记录或核对内核。清理临时检查脚本、预览、编译产物和缓存，保留教学必需的源码、配置、声明与资源。
