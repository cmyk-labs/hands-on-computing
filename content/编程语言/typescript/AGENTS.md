# TypeScript 课程补充协议

通用规则见[根协议](../../../AGENTS.md)与 [Notebook 协议](../../../docs/notebook-protocol.md)。范围与语言基线见 [plan.md](plan.md)，实际编译器、Node.js、配置和命令见 [README.md](README.md)，风格参考 [TypeScript 编程规范](TypeScript编程规范.md)。

## 类型讲解

- 依据对应版本 Handbook、TSConfig、发布说明与官方实现；区分类型和值、形参和实参、推断和标注、类型断言和运行时检查、约束和具体类型。
- 说明类型擦除与代码生成的边界；不能把类型、readonly、private 或类型断言说成自动产生运行时校验。旧式装饰器和新装饰器机制分开讲解。
- 默认具备所列 JavaScript 基础，不重复组织一套 JavaScript 入门课程。每个例子集中展示一个类型关系；泛型先说明输入输出的关系，再引入较复杂写法。
- 利用合理推断，不为所有局部变量机械加标注；不以 any、断言、@ts-ignore 或 skipLibCheck 绕过正在讲解的类型问题。
- 类型守卫、断言函数及外部数据校验是当前主题时可展示所需分支与合法、非法样例；不能以“来自外部”作为所有普通示例添加防护的默认理由。

## 展示与项目配置

- 源码用 typescript 或 tsx 代码块，配置和运行命令用对应标记；必要实际源码与 Notebook 保持一致。JSON、构建输出和锁文件不强塞不适用的源码头注释。
- 使用课程固定的项目内编译器；独立示例按项目或模块隔离，避免全局声明相互污染。检查采用对应配置的 tsc -p，不以单文件命令绕过项目设置。
- 主线显式启用 strict；附加检查选项在相关例子中说明。区分 target、lib、module、moduleResolution、宿主支持和 polyfill，不把 paths 当作自动改写运行时导入。
- 区分 Node.js 去除类型后运行与 TypeScript 编译器的静态检查；涉及实际生成代码的特性，要观察生成结果及运行行为。

## 验收

- 类型成功、预期诊断和运行成功分别检查；预期错误注明位置、原因与关键诊断，核对编译退出状态。
- @ts-expect-error 只能辅助确认存在错误，不能代替核对是否为预期诊断；不能用忽略指令使错误原因失去可见性。
- 运行时校验专题同时检查各个被讲解的情况；普通示例不为穷举非法输入扩展验收范围。
- 包发布、声明文件或消费者使用是教学目标时，以实际消费者安装及使用结果检查，不只确认当前源码可以编译。
