# JavaScript 教学写作补充协议

## 适用范围

适用于本目录及子目录中的 JavaScript 教学 Notebook、脚本、配置和配套资源。修改前读取[项目协作协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及本文件。章节范围以 [plan.md](plan.md) 为准，通用规则不在此重复维护。

正常工程代码遵循本目录的 [JavaScript 编程规范](JavaScript编程规范.md)。Notebook 为讲清知识点可以有意展示其他写法或反例，但须说明教学目的；最小入门片段不强制增加函数封装、JSDoc 类型或程序入口，也不要求批量重排既有代码。教学组织与实际检查仍按以下要求执行。

## 知识依据与术语

- 语言规则依据规划指定版本的 ECMA-262，国际化依据 ECMA-402。MDN JavaScript Guide 用于教学组织和用法对照；Node.js、npm、测试工具及浏览器行为分别查对应官方文档或标准。具体入口与章节对应关系见规划的“规划依据”。
- 写作前逐点核查直接支持正文和注释的具体小节。区分标准规定、引擎实现、宿主 API 和本例约定；提案阶段、已纳入的标准版本、运行环境支持分别确认，不把“ES6+”当作精确版本条件。
- 使用通行专业名称；闭包（closure）、暂时性死区（temporal dead zone）、实时绑定（live binding）等首次附英文并简述含义。译法不统一时保留英文，不自行创造分类或机制名称。API、关键字和工具名称保留原文。
- 区分原始值与对象、属性与变量、参数重新赋值与对象修改、可迭代对象与迭代器、Promise 状态与结果、语言作业与宿主任务。同一名称跨章出现时，用一句话说明关系和本章侧重点。
- 来源汇总到 Notebook 篇末，保留具体定位；不另建来源档案，不凭执行结果替代规范依据，不声称一份规划穷尽全部 API 和边界。

## 内容组织与解释尺度

- 采用“简短解释 → 最小 JavaScript 示例 → 必要边界”的顺序。每例围绕一个观察目的；基础语法直接讲用途，机制解释按执行步骤展开，不堆长文，也不把每句话拆成条目。
- 对象引用、闭包、this、原型链和异步调度须说明成立条件与原因。先给具体输入和正常写法，再按需要比较不同条件；反例用于澄清常见误解，不收集无实际用途的语法陷阱。
- 类型、运算符、同类方法需要总览时，可用“完整名称、中文名称／含义、用途”表格，每项一行；运算符、类型、方法和宿主 API 不混表。方法表按需列是否修改原对象与返回值，不替代正文中的条件说明。
- 路径、执行步骤、机制和排错使用短段落或以 - 起行的列表。首次出现的 x、回调参数、示例对象及省略号说明含义；运算符保留必要操作数，区分语法中的 ... 与表示省略的文字。
- 保留会影响使用的返回值、异常、原地修改、共享引用、空输入和资源清理说明。工程注意紧邻相应例子，不固定套用“基础／高阶／工程”三栏。
- 预期输出、检查重点和必要结果解释写在代码注释里；表格、正文和注释不重复解释同一句话。Notebook 正文不使用反引号行内高亮，代码块保留正常语法。

## Notebook 与配套脚本

- Notebook 是唯一教学正文。JavaScript 使用带 javascript 语言标记的 Markdown 代码块；命令和配置使用对应语言标记。配套原生脚本实际运行，不加入 Python 包装、魔法命令或要求读者先生成脚本的单元。
- 头部沿用学习目标、前置知识和“配套脚本：”要求；前置知识写概念和操作。有可执行示例时提供 scripts/二位序号-英文主题/ 下的对应文件、用途与完整命令，例如 scripts/19-es-modules/main.mjs。
- 配套脚本文件头按通用协议用 // 注释块标注四项信息，运行命令从本技术目录出发；预期错误的脚本在“期望结果”写明预期异常与非零退出。
- 纯语言示例以 Node.js 为默认执行环境，优先用 .mjs 明确模块模式；比较普通脚本、CommonJS 和 ES 模块时分别标明上下文，不把模块默认行为描述成所有 JavaScript 的行为。
- 正文片段与对应文件一致，保留当前例子所需的定义、导入和输入。示例从新进程运行，不能依赖控制台遗留变量或其他 Notebook；相关小例子可放在同一脚本，不为几行代码机械拆文件。
- DOM 等浏览器行为确有必要时才增加 HTML 页面，使用最少的 HTML/CSS，并注明宿主归属。课程不隐含要求先学框架、TypeScript 或构建工具。
- 模块和异步示例检查导入副作用、错误传播及任务完成；定时器、监听器、文件和进程按需要清理，不用随意延时掩盖竞态。

## 环境、路径与检查

- Node.js、npm 的安装与完整版本清单集中在本目录 README.md；章节头部链接该入口，保留语言版本、宿主、运行模式和工作目录。需要 Python 预览服务时单独说明；Notebook 阅读工具按通用入口准备。
- 操作说明采用 Step 短步骤，一步一句话、一个命令；首章关于控制台、脚本和模块运行的教学内容仍完整保留。
- 确需 npm 依赖时维护本技术目录的 package.json 与锁文件，用 npm scripts 提供重复操作入口；优先使用 Node.js 内置能力，不默认安装框架或全局工具。涉及多包结构时仅建立教学必需的包文件。
- 课程代码的固定路径使用完整相对路径字符串，有变量时只连接完整固定后缀，例如 new URL("./data/reports/summary.json", import.meta.url)；区分工作目录相对文件路径、模块说明符与 import.meta.url 的基准，移动文件后同步核对引用。
- 正常示例实际执行，核对输出、退出状态和副作用；预期错误独立演示并核对原因，不能忽略所有错误。异步检查确认真正完成，浏览器例子按需检查实际交互，不用语法检查代替运行。
- 检查覆盖、术语、引用定位、片段一致性、本地路径和正文渲染。只有 Markdown 的 Notebook 不要求内核计数与输出；若使用 Code 单元，则按通用协议执行。
- 实际检查范围与未验证平台只在交付说明报告；Notebook 不添加验证记录或核对内核。结束后清理临时检查脚本、预览、服务和运行产物，保留教学所需源码与资源。
