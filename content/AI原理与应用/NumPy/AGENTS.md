# NumPy 教学补充协议

适用于本目录及子目录。编写前读取[项目协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及 [Python 编程规范](../../编程语言/python/Python编程规范.md)。章节范围见 [plan.md](plan.md)，环境与运行入口见 [README.md](README.md)。

- 第 01 章[数组创建与形状](01-数组创建与形状.ipynb)的教学写法已获用户确认，后续章节以该样例为基准，按 plan.md 推进。章节独立提供输入和导入，不读取其他 Notebook 的变量或运行产物。
- 并行任务按单章分配，各章完成来源核查和空内核执行后交回审校，完成一章即补入下一章；同一 Notebook 只由一个编写者修改。计划、环境说明、依赖与总目录由协调者统一更新，避免并行覆盖。跨课程顺序见[项目方案](../../../docs/project-plan.md)。
- 按 plan.md 中的必讲、边界和选学范围组织内容；基础验收覆盖必讲与边界，不将选学机制作为后续主线的隐藏前提。
- 教学写法与现有 Python 入门章节保持一致，编写前对照[内置类型与运算](../../编程语言/python/02-内置类型与运算.ipynb)和[容器与对象引用](../../编程语言/python/04-容器与对象引用.ipynb)的讲解节奏与练习组织；具体格式仍以本协议和通用 Notebook 协议为准。
- 标题用简洁的概念或操作名称，如“数组形状与轴”“逐元素运算”。讲解直接说明含义、用法和必要边界，压缩重复的场景铺垫与操作提醒；不因精简而省略形状、轴含义或版本条件。
- 先用基本输入完成一次有明确用途的操作或计算，再展开其他写法、机制与边界，避免在首次计算前连续堆叠特殊情况。多种 API 服务于相近用途时，说明按什么任务条件选择。
- 基础示例以当前知识点所需的小数组为主，输入尽量就地给出；围绕同一任务的短流程可连续展示，复用变量时简要说明。综合任务放在“综合应用”中，不让独立知识点依赖贯穿全章的可变状态。
- 多维示例优先使用轴长不同、分组容易辨认的小数组，明确各轴含义；只有文字、嵌套列表和输出仍不易说明时再补示意图。
- 开篇依次单列“学习目标：”“前置知识：”“运行环境：”“环境准备：”“工作目录：”，工作目录写“本 Notebook 所在目录；重启内核后从上到下运行”。额外输入或运行条件仅在实际需要时补充。
- 练习逐题安排“题目 Markdown 单元 → Code 单元”；代码提供必要输入或待预测语句，填写处用注释标记，检查标准与必要提示写在注释中。预测题不在待预测语句旁给出答案，不用未定义名称或主动报错占位。
- 练习兼顾操作、预测和方法选择；至少一道题改变任务条件或增加约束，要求解释选择理由。优先改造现有题目，避免只靠更换数字或增加 API 扩充练习。
- 篇末来源统一使用“网站／本章参考内容与定位”两列表格，同一网站一行，保留版本、直接链接和必要小节定位。排版统一不替代写作前的来源核查。
- Notebook 工作目录统一为本课程目录；固定文件路径写完整相对字符串，变量只连接完整固定后缀。优先使用单元内小数组与临时文件，需要保留的配套资源才放入 `scripts/二位序号-英文主题/`。
- 用 `import numpy as np`。先解释当前示例的数组形状和轴含义，再引入批量写法；不在基础章提前堆入 einsum、底层缓冲区或工程封装。
- 观察结果按通用协议用 print() 展示；预期特征和结果解释写在代码注释中。尺寸较大的数组只打印有教学意义的局部或摘要。
- 索引和赋值实验同时检查值、shape、dtype 与必要的共享关系；不要只凭变量名、base 或“没有报错”判断副本及正确性。
- 数值实验区分精确比较与容差比较；说明容差依据、非有限值处理及统计口径。矩阵求解或分解检查残差、重构误差及输入条件。
- 随机实验使用局部 Generator，写明种子与必要的生成器条件；不将样本统计量当成精确理论值，不承诺跨版本或跨后端逐位一致。
- 性能实验先核对结果，再测量有限规模的实际耗时；区别数组存储量、中间数组与进程内存，不预填固定跑分或加速倍数。
- 来源以与环境匹配的 NumPy 官方文档为主。版本差异和旧接口就地说明；数学性质超出 API 文档支持范围时，先补核权威来源再写正文。
- 从空内核顺序运行并保存真实输出；文件资源及时关闭和清理。可执行逻辑、环境或输入变更后重新执行；仅改说明或注释时按通用协议核对已有输出及必要的刷新范围。实际检查结果只在当次交付说明报告。

- 本课程配套 CSV、Excel 教学输入按约定放在 `date/`，文件名使用二位章节号与英文小写 kebab-case；头部“配套脚本：”注明无外部脚本并列出数据文件与用途。小数组、小表仍优先在单元内构造，生成的临时导出文件不写回 `date/`；示意图与真实截图放在 `image/`。
