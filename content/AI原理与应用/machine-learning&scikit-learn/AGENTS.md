# 机器学习与 scikit-learn 教学补充协议

适用于本目录及子目录。编写前读取[项目协议](../../../AGENTS.md)、[Notebook 编写协议](../../../docs/notebook-protocol.md)及 [Python 编程规范](../../编程语言/python/Python编程规范.md)。通用教学组织、长代码注释、输出预期、命名和分支取舍统一执行[七条原则](../../../docs/notebook-protocol.md#课程编写的七条原则)，本文件只补充机器学习课程要求。

课程范围、实施状态和来源入口见 [plan.md](plan.md)，环境版本与运行步骤集中维护在 [README.md](README.md)。未完成来源核查与实际执行的章节不得标记为已实施。

## 课程依据与分章

- 课程结构参考权威教材和正式课程；算法解释依据已核查的作者教材、官方讲义或原始论文，框架行为依据对应版本的官方文档。具体来源与主题对应关系集中在 plan.md，不将本项目自行编排的目录称为官方课程目录。
- 现有主题编号用于维护覆盖范围，不固定最终章节数量。分章由前置概念、完整推导和基础实现的篇幅决定；多个算法不能因共属一个库模块就挤在一章。
- 每章规划写明理论来源定位、推导范围、手写算法及其变体、框架对照、需要复用的模块和核对目标；框架版本引用 README.md 中实际验证的版本。尚未核查的推导不得宣称已有充分依据，也不得直接写入正文。

## 算法教学顺序

算法章统一按“问题与直觉 → 假设和符号 → 公式与推导 → 小样本计算 → Python 手写实现 → 框架实现 → 对照实验 → 练习”展开。作为独立算法正式讲授的方法必须完成这条流程；仅介绍用途的方法标明“概览”，不计作完整算法教学。入门接口、数据处理、工具与综合应用主题按其学习目标组织，不机械增加不存在的模型训练过程。

- 先说明任务、输入输出、模型假设和适用条件，再给公式。首次使用 X、y、w、n 等符号时说明含义、维度、范围和必要单位，明确样本轴、特征轴和类别列。
- 解释目标函数或决策规则的由来，逐步推出求解、更新或预测规则；说明关键等式所用条件，不能用“显然”跳过当前学习目标需要的推理。核心推导必讲，额外定理的完整证明可标为选学，数值实验不替代证明。
- 公式与推导保留在 Markdown 数学排版中。手算结果、代码变量和公式符号相互对应；操作说明及预期输出写在相邻注释中。仍按知识点组织 Markdown 与 Code 单元，复杂算法分步展开，不把整章挤成两个单元。

## 手写实现与框架对照

- 手写版默认使用 Python + NumPy，可使用数组、矩阵运算和必要线性代数基础函数；当前讲授的核心算法必须自行实现，不能调用现成估计器或将整个求解过程交给通用优化器后称为手写版。讲解求导时显式计算梯度，自动微分放在框架版解释。
- 手写版是能够完成约定任务的基础算法：训练型算法包含必要的拟合、迭代与停止条件，预测或变换型方法包含完整计算过程。一次梯度更新、一次树切分、一次 E/M 步仅是过程演示，不算完成算法实现。
- 明确简化范围、输入条件、计算成本和失效情形。例如线性 SVM 的实现不代表已实现核 SVM，浅树实现不能省略递归构建与预测；扩展算法实施时同样遵循本协议。
- 传统机器学习默认提供 scikit-learn 对照版。线性模型、逻辑回归、梯度训练及多层感知机可使用 PyTorch 展示张量、自动微分和优化器；按主题选择，不强制每种算法同时编写两个框架版。首次使用 PyTorch 时讲清必要接口，不提前引入训练框架封装。
- 对照前明确数据划分、预处理、初始化条件、数据类型、损失的求和或平均、截距、正则化、样本权重与停止条件。按已知解、目标值、预测或必要数值关系核对；有合理实现差异时解释原因，不要求参数逐位一致。
- 对可微手写模型按需用有限差分等方式核对梯度。对数、指数、除法和矩阵求解中的稳定处理要说明数学作用与适用条件；必要的平滑、正则化、停止判断和资源清理不属于多余防御。

## 数据、脚本与图片

| 位置 | 用途与约定 |
| --- | --- |
| data/ | 所有落盘教学数据，包括原始图像数据集；按数据集组织，需要时再区分 raw/ 与 processed/。原始数据不被处理流程覆盖。 |
| scripts/ | 可复用的数据加载、处理、评估、绘图和算法模块；直接导入的模块与包用 snake_case，例如 scripts/linear_regression.py。跨章模块不放进带连字符的章节目录。 |
| scripts/二位序号-英文主题/ | 确需独立运行、且仅供单章使用的命令行脚本与代码配套文件；数据仍归 data/。 |
| image/illustration/ | 辅助学习的模型结构、算法流程、机制与几何示意图；编号、扩展名和复用遵循通用图示要求。 |
| image/ | 需要保存或复用的实际成图与截图；一般绘图直接保留 Notebook 输出，不存放训练用图像数据集。 |

- 以上是文件归属约定，有实际内容时才创建目录，不建立空目录、占位数据或提前搭建脚本工程。用于手算的少量数组可就地定义，重复使用的落盘训练数据统一进入 data/。
- 数据说明记录来源、许可、字段、单位、目标列、必要版本与生成条件；就近放在数据集说明或课程 README 中，不另建来源归档。合成数据明确标注，不作为真实业务效果证据。
- Notebook 工作目录统一为本课程目录。固定路径写完整相对字符串，命令中包含 `&` 的路径加引号；开篇“配套脚本：”列出实际脚本及用途，另用“数据：”列出数据路径和字段说明入口。
- 脚本文件头遵守通用协议四项要求。共享模块的“所属章节”标明首次讲解的章节，可补充复用主题；公开函数简述输入、返回值及必要形状，不维护另一份课程正文。
- 模型文件、缓存、大型下载数据与临时输出不提交；保存模型的实验说明实际输出位置和清理方式，不能把模型权重混作教学数据提交。

## 首次讲解与后续复用

- 数据读取、字段选择、划分、预处理、评估、绘图和通用训练循环，首次在 Notebook 中展开并解释，通过实际核对后再抽取到 scripts/。后续章节导入使用，简述函数用途、返回值、可配置条件并链接源码，不重复粘贴完整准备流程。
- 当前学习的算法、损失、梯度或新增更新规则始终在当前 Notebook 展开。相同训练流程可以复用，但不能把本章重点隐藏在未讲解的辅助函数或类中；初次展示的代码与抽取后的模块保持一致。
- 模块导入只提供定义，不自动训练、下载或读写数据。拟合得到的状态由本次调用显式创建或传入；数据划分、种子及影响结果的参数可在调用处辨认，不藏在全局可变对象中。
- 预处理复用函数或未拟合流程的构造方式，不跨验证折复用已拟合的标准化器、选择器或模型。每章从空内核独立准备输入和必要状态，不依赖其他 Notebook 已经运行或生成文件。
- 修改共享模块后同步核对首次讲解代码与所有受影响的调用；可执行行为改变时重跑相应章节，不能仅验证模块能够导入。

## Notebook 中的可视化

- 适合用图解释的内容就地展示，例如数据分布、损失曲线、梯度轨迹、决策边界、树结构、聚类中心移动和降维结果。图形紧接相关代码输出，与公式和数值结果配合阅读。
- 优先直接显示代码生成的图形，使用相应工具的显式展示接口，如 Matplotlib 的 plt.show()；保存实际执行得到的静态图形输出，使读者打开 Notebook 即可查看。无需将每张输出另存为文件再读回。
- 实际成图需要 Markdown 引用、跨章复用或导出时，才另存到 image/；辅助学习示意图归入 image/illustration/。文件图片以相对路径引用，并说明用途、来源或授权。实际运行结果不能用人工绘制的图片冒充。
- 绘图代码旁说明坐标、单位、颜色或类别、预期现象及比较重点；不只写“绘制图形”。实际数据与图形一致，图中文字清晰，多模型比较保持合理的坐标和评估条件。
- 可选动画或交互展示需实际检查，并保留足以说明核心结论的静态输出；不能假定保存 Notebook 就保存了所有交互状态。

## 模型结构图与算法流程图

- 按学习需要加入模型架构图、算法流程图或原理示意图，辅助理解模型组成、数据流向、迭代更新及训练与预测的区别。每图围绕一个明确问题，与相关公式和代码相邻；简单文字已能讲清的内容不强制配图，图示不替代推导与实现。
- 图源选择和自绘风格统一遵循[通用图示要求](../../../docs/notebook-protocol.md#图示的制作与整合)：优先使用适合本节且可用的权威原图，没有可用原图时再依据权威资料自行绘制。自绘图参考协议中指定图例的配色、线条和文字层次，布局按算法关系设计；引用原图保留其风格。
- 图形随语义选择：模型图表达层、节点及连接，流程图表达步骤、判断和循环，几何示意表达空间关系。明确箭头表示数据、计算顺序还是梯度；多种含义并存时用文字或图例区分，实线与虚线的用途保持一致，不只靠颜色传达区别。避免交叉连线和无意义装饰。
- 图中文字简短，符号、维度、步骤顺序和模型变体与正文及代码一致；按需标注输入、输出、关键运算、判断条件和停止条件。图下注明阅读重点、简化范围，并提供替代文本；人工示意明确标为示意图，不作为实际运行结果。
- 模型与算法图优先查找官方文档、原始论文或作者发布的教材与课程资料。除通用的出处、许可和清晰度检查外，重点核对模型变体、训练与推理阶段、张量维度、损失定义和当前推导的简化条件；不能以相近模型的图替代本章实现。来源、改绘标识和章末引用按通用协议维护。
- 自绘图的制作、字体检查、编号、扩展名与跨章复用执行[通用图示要求](../../../docs/notebook-protocol.md#图示的制作与整合)：含文字、公式或精确连线的图采用 SVG 或 Python 绘制，非必要不直接使用图像生成模型。辅助学习示意图放入 image/illustration/，正文用相对路径引用；SVG 保留 .svg。实际代码成图仍可保留在单元输出，不要求额外导出；仅在有实际图片时创建目录。
- 验收时在 Notebook 的实际阅读视图检查文字、公式、箭头、图例与缩放后的清晰度，避免裁切、遮挡和过密排版；同时核对图意与来源、推导、代码的一致性。算法或模型结构变更时同步更新图示。

## 实验设计与验收

- 小型示例保留普通 CPU 可复现的路径；适合 GPU 的模型训练可以按需使用 GPU。先确认框架支持、设备及当前可用显存，为模型、数据、梯度和优化器状态留出余量；实际记录设备、框架与 CUDA 版本、批次大小和峰值显存，不凭总显存推断所有实验都能运行。GPU 配置集中在 README.md，未执行的分支明确说明。
- 先确定预测目标、预测时可用字段和样本关系，再选择独立、分组或时间划分。特征处理、特征选择、超参数、早停、校准与阈值都按各自训练和验证边界实施；最终测试集保留到开发流程固定后使用。
- 比较模型时说明划分、指标、基线和搜索预算。无监督示例区分结构探索与新样本应用，说明是否存在参考标签及评估条件；每种方法说明假设、主要参数、计算成本及不适用情形。
- 核对手算、已知解、梯度或必要数值关系，不能以“没有报错”代表算法正确。预测输出说明形状、类别或列顺序，指标注明方向和单位；随机结果写稳定特征或本次观测，不预设分数与模型排名。
- 控制数据生成、划分和估计器中相关的随机性，按 API 支持的类型传入随机状态；不把一个全局 NumPy 种子视为控制所有随机源。对照数据类型、数值容差和必要的后端差异。
- 正常教学路径不包裹兜底异常或批量屏蔽警告。收敛警告结合缩放、求解器和迭代条件解释；无效参数反例按 Notebook 协议标记预期异常。
- 练习兼顾推导理解、实现修改和方法选择，至少一道题改变数据条件、划分、指标或参数范围。重点题提供分层提示与解析，预测题只提示运行后的核对维度。
- 正文实施后从空内核执行，核对公式、注释、真实输出、图形和练习；模型保存示例核对重载后的完整流程。安装、静态检查、已有输出核对与实际执行分别报告；尚未验证的环境或分支明确列出。
- 章末按网站汇总来源，同一网站一行，保留直接页面、小节、论文页码或必要版本，并说明其支持的理论或实现内容。规划的主题映射不替代写作前逐项核查，也不替代章节自身的引用。
